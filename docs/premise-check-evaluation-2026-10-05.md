# 証明する前に聞き返す（PFR-014）— 実モデルでの評価（2026-10-05）

仕様：[PFR-014](../specs/proof-request-reuse/requirements.md)。実装：pals-agent `4bc1433`。評価スクリプト：[`pals-scripts/premise-check-eval.py`](../pals-scripts/premise-check-eval.py)。

## 何を変えたか

質問を受けたら、Lean の前の評価段階（preflight）で次の 3 つを確認する。

- **反例**：書かれたとおりの命題に、具体的な反例（0・1・−1 などの境界値や、よく知られた反例）がないか。
- **真偽を左右する未指定の選択**：体（ℝ か ℂ か）、数の範囲（ℕ か ℤ か）、0 でないという条件など。
- **慣例として採った読み方**：真偽に影響しないもの。質問はせず、評価した命題の文に明記する。

反例か真偽を左右する選択があれば、Lean にかける前に `needs_input` で聞き返す。反例は「成り立たないようです」と推測として示し、選択肢には次のものを並べる。

- 意図していそうな正しい命題
- そのまま証明を試す

選択肢に出す命題は、自分も同じ反例チェックを通るものに限る。「そのまま」を選んだ人には、同じことを二度聞かない。

モデルが問題を報告したのに聞き返さなかった場合は、4 言語の定型文で必ず聞き返す。チェックの結果は非公開の証跡として記録する。

## 途中で直したこと

- **選択肢に偽の命題が出た。** 1 回目の調整で、「n が奇数なら n²+n は奇数」（実際は偶数）や「x²+1 は複素数の根を持たない」が、意図していそうな命題として選択肢に出た。選択肢の命題にも同じ反例チェックを課し、自信がないものは出さないようにした。
- **聞き返しすぎ。** 「有限整域は体」で、整域が零環を含むかを聞き返した。教科書の標準的な定義（整域や体では 1≠0、素数は 2 以上）は未指定の選択ではなく、既定値として扱うようにした。

## 限界と次の段階

- 反例はモデルが出すもので、Lean で確かめてはいない。そのため、質問文では「成り立たないようです」と推測として示す。モデルの推論は間違うことがある。例として、「そのまま」を選んだ後のチェックに「正の自然数なら成り立つ」という誤った記述があった（回答には使われない）。次の段階は、反例を Lean（`decide` や具体的な値）で確かめることと、証明が失敗したときに否定を証明して「偽です（Lean 検証済み）」と示すこと。
- 選択肢の細部はまだ完全ではない。例：「複素ベクトル空間上の線形写像は固有値をもつ」に「0 次元でない」が抜けた。Lean の検証と意味レビューで止まる範囲だが、品質の余地がある。
- 実際の画面での確認（偽の命題 → 聞き返し → 正しい命題を選んで Lean で証明、「そのまま」を選んで二度聞かれない）は未実施。評価の時点で、共有のローカル環境の API・画面・worker が別セッションのイメージに入れ替わっていたため。
