## 1. 解決したい課題

### 課題

AI がコードや文章を生成する時代に、出力の正しさをどう保証するかは教育・研究・産業に共通する大きな課題です。特に数学、アルゴリズム、セキュリティ、金融、医療、インフラなど、誤りのコストが高い領域では「それらしい説明」ではなく、機械的に検証できる根拠が必要になります。

Lean などの定理証明支援系は、証明や仕様を機械的に検証できる強力な技術です。一方で、初学者にとっては以下の壁があります。

- 自然言語の証明を Lean の文法・型・戦術へ変換する認知負荷が高い。
- コンパイルエラーや tactic state を読んで修正するには経験が必要。
- 既存の LLM は Lean コードを生成できても、誤った証明や `sorry` を含む出力を返すことがある。
- 教員・TA 側も、学習者の詰まりどころや証明過程を継続的に把握しにくい。

この結果、形式証明は「社会的には重要だが、学び始めるまでの摩擦が大きい」技術になっています。

### ビジョン

PALS は、形式証明を一部の専門家だけの道具から、数学・情報科学を学ぶ学生、研究者、実務者が日常的に使える検証インフラへ広げます。目指すのは、AI が答えを代筆する環境ではなく、学習者が自分の証明を組み立て、Lean によって検証し、失敗から修正できる環境です。

初期ターゲットは、Lean や形式手法を学びたい大学生・大学院生、授業やゼミで形式証明を扱う教員・TA、数学/CS 研究室です。将来的には、セキュリティ・金融・AI 安全性など、高信頼な仕様検証を必要とする企業研修や開発現場にも展開します。

## 2. 解決策: PALS のプロダクト

PALS は、Lean verifier を中心にした学習・証明支援システムです。自然言語の問題や証明方針を入力すると、AI agent が証明を小さなサブゴールへ分解し、Lean の proof sketch を作成し、Lean compiler/verifier の診断を受けながら修正案を提示します。

### MVP の主要機能

1. 問題入力
   - 自然言語の定理、Lean の theorem statement、授業課題を入力できる。
   - 学習者向けには、いきなり完成証明を出すのではなく、サブゴールとヒントを段階的に提示する。

2. Draft, Sketch, and Prove ワークフロー
   - Draft: 自然言語で証明方針とサブゴールを整理する。
   - Sketch: Lean の `have` 文、補題、穴あき proof skeleton に変換する。
   - Prove/Repair: Lean diagnostics を読んで tactic や証明断片を修正する。

3. Lean verifier-in-the-loop
   - AI の出力を必ず Lean で検証する。
   - `sorry` や `admit` を最終成果として扱わない。
   - 成功/失敗、コンパイルエラー、修正履歴、実行時間を保存する。

4. 学習者向けフィードバック
   - エラーの意味を日本語/英語で説明する。
   - 次に見るべき仮定、使えそうな lemma、証明の分岐を提示する。
   - 「なぜこの修正が必要か」を学べる形で表示する。

5. 教員・研究者向けトレース
   - どの問題で詰まったか、どのエラーが多いか、どのヒントで改善したかを記録する。
   - 授業改善、教材作成、Lean 学習データセット構築に活用できる。

### 技術構成

現時点の設計では、Web frontend、FastAPI backend、LangGraph agent、Lean verifier runtime、trace database、artifact storage で構成します。Lean verifier は独立リポジトリではなく、`pals-agent` 内の agent tool/runtime として管理し、本番では agent とは別 process または sidecar container として動かせる設計にします。

ローカル実験では Ollama と Qwen 系モデルを使い、低コストに draft/sketch/prove/repair の検証を行います。共有開発・本番では Bedrock などの managed LLM を利用し、月額 JPY 80,000 の MVP 予算ガードレール内で、scale-to-zero / pay-per-job を前提に設計します。

## 3. 顧客・市場・ビジネスモデル

### 初期顧客

最初に狙う顧客は、形式証明を学びたい大学生・大学院生と、その学習を支援する教員・TA です。早稲田大学内では、数学、情報科学、ソフトウェア工学、セキュリティ、AI 安全性に関心のある授業・ゼミ・研究室が初期検証先になります。

初期の利用シーンは以下です。

- Lean 入門演習で、学生が証明エラーを理解するための補助教材として使う。
- 研究室で、定理やアルゴリズムの形式化を試す探索ツールとして使う。
- 自習者が、自然言語の証明から Lean proof sketch へ移る練習に使う。
- 教員・TA が、課題ごとの詰まりどころを把握し、教材改善に使う。

### 事業化仮説

初期は教育・研究用途に絞り、以下の収益仮説を検証します。

- 大学授業・ゼミ単位の SaaS ライセンス
- 研究室向けの hosted workspace / private deployment
- 企業向け形式手法・Lean 研修パッケージ
- 高信頼ソフトウェア開発向けの proof-job API / verifier trace platform

OSS として公開する `pals-agent` は研究・開発コミュニティへの信頼獲得と外部貢献の受け皿にし、ホスト型 UI、チーム管理、授業管理、トレース分析、セキュリティ管理を商用価値として提供する方針です。

### 競合と差別化

一般的な生成 AI、コード補完、Lean 専用研究プロジェクトはすでに存在します。しかし PALS は以下の点で差別化します。

- AI の回答をそのまま信じず、Lean verifier の結果を中心に体験を設計する。
- 完成証明の自動生成だけでなく、学習者が証明を理解して進める UX に重点を置く。
- 日本語でのエラー説明、授業利用、国内大学での導入を初期から想定する。
- 成功例だけでなく失敗・修正履歴も保存し、教材改善と将来の fine tuning データに活用する。
- ローカル LLM と managed LLM を使い分け、コストを抑えながら検証回数を増やす。

PALS の価値は「Lean コードを生成すること」だけではありません。価値の中心は、証明を検証可能な単位に分解し、AI の提案と Lean の診断を往復させ、学習者・教員・研究者が再利用できる形で知識化することです。

## 4. ギャップファンド期間中の検証計画

### 検証したい主要仮説

1. 学習者課題仮説
   - Lean 初学者は、文法そのものよりも、goal state / error message / 使用可能な lemma の読み解きで詰まっている。

2. 解決策仮説
   - PALS のサブゴール分解、proof sketch、エラー説明により、初学者の「最初の検証済み証明」までの時間を短縮できる。

3. 教員価値仮説
   - 教員・TA は、個々の答案だけでなく、失敗履歴や詰まりどころの集計に価値を感じる。

4. 事業性仮説

### 主要リスクと対策

| リスク | 内容 | 対策 |
| --- | --- | --- |
| 技術精度 | LLM が Lean 証明を安定生成できない | 完全自動証明ではなく、Draft/Sketch/Repair と verifier feedback を中心に設計する |

| データ管理 | 学習ログや研究利用時の同意が必要 | 個人情報を最小化し、同意取得、匿名化、保存範囲を明確化する |

## 応募フォームに書く短文案

### 事業アイデア名

PALS: Proof Assistant Learning System

### 事業アイデアの概要

PALS は、Lean などの定理証明支援系を学ぶ学生・研究者に向けた、AI と Lean verifier を組み合わせた学習・証明支援プラットフォームです。自然言語の問題をサブゴールへ分解し、Lean の proof sketch を生成し、Lean の診断をもとに修正案と解説を提示します。AI の出力をそのまま信じるのではなく、機械的検証を中心に置くことで、形式証明の学習障壁を下げ、将来的には高信頼ソフトウェアや AI 安全性領域で使える検証基盤を目指します。

### 解決したい社会課題

生成 AI の普及により、出力の正しさを検証する力がますます重要になっています。しかし、形式証明や Lean は有用である一方、初学者には文法、型、tactic state、エラー修正の壁が高く、教育・研究・実務に広く使われるにはまだ摩擦があります。PALS は、検証可能な AI 学習環境を作ることで、数学・情報科学教育、セキュリティ、AI 安全性、高信頼ソフトウェア開発に貢献します。

### ギャップファンドで実施したいこと

期間中に、Lean 入門課題を対象とする MVP を開発し、早稲田内外の学生・教員・研究者へのヒアリングとユーザーテストを行います。具体的には、問題入力、proof sketch 生成、Lean verifier 実行、エラー説明、修正履歴保存までの最小プロトタイプを作り、初学者の time-to-first-verified-proof、詰まりどころ、教員側の導入価値を検証します。得られたデータをもとに、授業・ゼミでの pilot、研究室連携、教育向け SaaS への事業化可能性を判断します。

### 自分たちが取り組む理由

PALS は、単なる生成 AI プロダクトではなく、AI の不確実性を Lean verifier によって検証し、学習者が理解しながら証明を構築できる体験を目指しています。既に repo 構成、Lean verifier の管理方針、local/cloud LLM の設計、AWS MVP architecture まで整理しており、ギャップファンド期間中に実際のユーザー検証へ進める準備があります。
