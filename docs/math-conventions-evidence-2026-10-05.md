## 確認したこと

### 実 PostgreSQL（pals-api `tests/integration/test_math_conventions.py`、9 件すべて成功）

- release step の新規適用と再適用（no-op）。適用後に表を変えると current でなくなり、再適用も拒否する。
- 設定一覧に 11 項目が並び、未設定は「確認する」。1 項目を変更して戻せる。カタログにない ID とゲストは拒否する。
- release 前は、設定 API が 503 になり、claim に約束事が付かない。確認の質問は `math_conventions_unavailable` で失敗する。
- 確認の質問は、API がカタログの文言と 3 つの選択肢に置き換える。
  - 「今回だけ」は、その要求だけに効く。設定は「確認する」のままで、別の要求には効かない。
  - 「常に」と「含めない」は設定に保存される。同じ項目の確認は以後拒否する。
  - 自由記述の答えは設定を変えない。
- worker が報告した読みは、今回の答え・設定・（ゲストのみ）既定のどれかと一致しなければ拒否する。一致した読みは、出どころとともに公開応答と一覧に出る。
- ゲストは方針が `default` で、確認の質問は拒否される。既定の読みは出どころ「標準」で記録される。

既存の proof request・Lean・ゲスト・local legacy release の結合テストにも退行はない。ただし環境依存の既存の失敗（ロール・fixture の不足、レプリカの local legacy テスト 1 件）は変更前の HEAD でも同じように失敗する。

- 約束事の 5 件は、修正後の 2 回とも期待どおりだった。

### 見つかった問題と修正

1. **ℕ を 1 から始めると、正しい証明が独立レビューで却下される。** Lean は `∀ n : {n : ℕ // 1 ≤ n}, 1 ≤ n` と忠実に形式化した。しかしレビューは、約束事を知らないまま「0 を除いた弱い主張」として却下した。要求文に書かれた約束事は主張の一部として扱うようにした（agent `acbf707`）。
2. **零環を含めると、「体」が「0 でない元が可逆」に弱められたまま検証済みになりかけた。** レビューが「約束事のもとで零環は自明に満たす」と通した（このときは説明レビューが却下し、回答は出なかった）。約束事は名前の付いた概念だけを変え、他の定義（体は 1 ≠ 0 など）は標準のままとした。結論を弱めた証明は拒否する（agent `9b4cff7`）。採用した読みと「他の定義は標準」という一文を、Lean の命題に必ず書き込むようにした（agent `89d03d1`）。
3. 既知の課題：Lean ジョブが 1 件ずつしか処理されないため、質問の評価も待たされる（別セッションが worker の分離を進めている）。

### 修正後の再確認

| 確認 | 結果 |
|---|---|
| ℕ を 1 から始める（設定） | Lean で検証済みの回答になった。「この回答の前提：自然数は 1 から始める（設定）」。 |
| 零環を含める（設定） | 修正後のレビューが、弱めた結論を却下した。Lean で検証できず、回答は出ない（主張はこの読みでは偽なので正しい結果）。 |

ただし零環の再確認では、評価段階のモデルが、反例で聞き返す代わりに、要求を「この読みでは成り立たない」という主張に**書き換えて**進めた。結果は回答なしで安全だが、「この読みでは偽で、零環が反例です」と学習者に伝えるのが望ましい。反例を Lean で確かめて示す次の段階（PFR-014 の残り）で扱う。
