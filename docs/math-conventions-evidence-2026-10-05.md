## 確認したこと

### 実 PostgreSQL（pals-api `tests/integration/test_math_conventions.py`、9 件すべて成功）

- release step の新規適用と再適用（no-op）。適用後に表を変えると current でなくなり、再適用も拒否する。
- 設定一覧に 11 項目が並び、未設定は「確認する」。1 項目を変更して戻せる。カタログにない ID とゲストは拒否する。
- release 前は、設定 API が 503 になり、claim に約束事が付かない。確認の質問は `math_conventions_unavailable` で失敗する。
- 確認の質問は、API がカタログの文言と 3 つの選択肢に置き換える。
  - 「今回だけ」は、その要求だけに効く。設定は「確認する」のままで、別の要求には効かない。
  - 「常に」と「含めない」は設定に保存される。同じ項目の確認は以後拒否する。
  - 自由記述の答えは設定を変えない。
- worker が報告した読みは、今回の答え・設定・（ゲストのみ）既定のどれかと一致しなければ拒否する。一致した読みは、出どころとともに公開応答と一覧に出る。
- ゲストは方針が `default` で、確認の質問は拒否される。既定の読みは出どころ「標準」で記録される。

既存の proof request・Lean・ゲスト・local legacy release の結合テストにも退行はない。ただし環境依存の既存の失敗（ロール・fixture の不足、レプリカの local legacy テスト 1 件）は変更前の HEAD でも同じように失敗する。

### 実モデル（`pals-scripts/premise-check-eval.py`、`PALS_EVAL_CONVENTIONS=1`）

- 約束事の 5 件を追加した。整域と零環、ℕ の 0、コンパクトとハウスドルフ、0⁰、設定済みの読み。
- 約束事あり（設定は未選択）で 31 件を実行した。
  - 1 回目は 28/31。この結果から 2 点を直した。
    - 真偽が読みで変わらない約束事は聞かず、反例として扱う。
    - モデルが確認をシステムに任せる出力を受け付ける。
  - 修正後は 29/31 と 30/31。外れは毎回 1〜2 件で、毎回違うケースだった（モデルの判断の揺れ）。
    - a² ≥ 0 と「n² が偶数なら n は偶数」で数の範囲を聞いた。
    - 「そのまま」を選んだ後に ℕ の 0 を聞いた。
- 約束事の 5 件は、修正後の 2 回とも期待どおりだった。
  - 零環・ℕ の 0・ハウスドルフ・0⁰ を確認した。
  - 設定済みの「整域は 1 ≠ 0」は確認せずに進んだ。
  - 「有限整域は体」は、約束事ありでは零環を確認する（約束事なしでは標準の定義で進む）。
- 約束事なしの 26 件は 25/26。外れは x/x = 1 を聞かずに進めた 1 件。
