## 表示と状態の扱い

アイコンと本文の間隔を既存の回答列と揃え、状態と時計を同じ行へまとめる。長い状態文は本文列内で折り返す。時計は要求のサーバー作成時刻を基準にし、検証開始でリセットしない。

途中表示は未検証と明示する。生成中の実際の内容だけを使い、コンパイルと修復の間は直近の内容を保つ。終端・所有権の喪失時は消す。動きを減らす設定や強制色では、タイトルのアニメーションを止めて静止アイコンを出す。

チャット移動時の保持対象はアカウントと認証epochで分け、ブラウザーの永続ストレージには保存しない。別アカウントのデータは即座に隠す。既知のプランを表示していても、最新の利用枠を再取得するまで送信を許可しない。

## ゲストAPIの確認

[API PR #121](https://github.com/AtsushiHosaka/pals-api/pull/121)に実装した。APIの開始ソースは`eebb1abf7c010c3a13c1179a810db82e2b142e5e`、変更は`9829110`。本人のcookieで取得できる既存のLean経路に、opt-inヘッダーを付けた場合だけ途中表示を追加した。要求とジョブの状態を同じSQLのsnapshotで読み、終端になった要求の途中内容を返さない。所有権・claim期限・段階の検査と、既存の出力モデルを再利用した。

担当と親担当が独立して35件ずつ確認し、うち5件は実HTTPと専用テストPostgreSQLを使った。保存するジョブ状態はfixtureであり、実モデルやLeanの実行成功を示すものではない。一時DBを使い、実行前後のテストDB一覧が一致した。別担当の独立レビューと対象30件も成功し、追加SQLのsnapshot変更もレビューした。Ruffと対象ソースのmypyは成功した。

既存ゲスト全体の試験では50成功・1失敗。変更していないPOST answersのfixtureにnotifierがない失敗で、開始ソースでも再現した。今回の修正で解消したとは扱わない。
