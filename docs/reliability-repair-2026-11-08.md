# リリースと回答の不具合修正

担当はCodex。進行は[#309](https://github.com/AtsushiHosaka/pals/issues/309)、変更は親PR #310、API PR #90〜#92、Web PR #61〜#63、Infra PR #108で追います。

## 実施した修正

APIは、説明の最後にある結論を回答本文へ保存するようにしました。旧版では失敗する回帰テストを確認したうえで修正しています。実PostgreSQLで保存本文を別途照会し、新しい接続から二度読み直して、公開APIの応答形式にも結論が一度だけ残ることを確認しました。Leanの参照、反証、文字数上限は維持しています。既存の保存済み回答の補正は行っていません。

実検証では、結果を保存できなかったとき、再試行の予約がNOOP扱いで消える別の不具合も見つかりました。保存の成否が不明な場合は、確定済みの成功を読み直すか、保持中のリース期限に再試行するように修正しました。保存していない結果を成功にせず、課金の依頼も再送しません。旧版で失敗する回帰と実行器の試験を追加し、API PR #92を統合しました。

Webは、一時的な通信失敗のあとも同じ依頼を観測し直すようにしました。再試行間隔は2・4・8・16・30秒で、読取は一度に一つ、通信の期限は20秒です。画面の復帰やオンライン復帰でも再観測します。認証拒否、不正な応答、終端状態では自動再試行を止めます。課金処理を再送して回復したように見せる実装ではありません。

回答の検証には、依頼と表示本文を結ぶDOM属性を追加しました。受入ゲートは、実APIでの完了・保存、結論を含む本文、実画面の表示、再読込後の一致を確認します。候補の署名、実イメージ、ソース、設定も照合します。SSMでは環境変数のハッシュをホスト内で計算し、値を取り出さずに検査します。

切替処理は、コードをリポジトリで管理する実行器へまとめました。通信を止める前に、実CI、承認されたローカル環境での受入、最新の事前検査、復旧経路を検査します。DB切替の応答を失った場合は、実DBと遠隔処理の状態を調べます。旧版のままで遠隔処理も止まっていると確認できた場合だけ復旧します。更新が続いているか状態が分からない場合は、切替の所有権を解放しません。

事前検証には実PostgreSQL、実Lean、実モデルを使い、本番の認証と通信は現在Chromeでログインしているアカウントから一件送って確かめる、という方針がユーザーに承認されました。AWSに別の検証環境は作りません。ローカルで代用する認証、キュー、DB権限、通信制御、予算制限の境界を記録し、本番と同じだとは扱いません。

単一のALB接続先を登録解除する現行方式では、正常な切替中にも計画的な503が残ります。今回の事前検査と復旧修正は、失敗後に停止が長引く原因を防ぐものです。無停止化には、旧版の読み取りを維持する互換性設計か、複数の接続先を使う切替方式の検証が必要です。

## 開発ルールの適用

APIとWebの本番ソース基準ブランチに、実CI、PR経由の変更、管理者への適用、強制push・削除の禁止を設定しました。修正は必須CIを通して、この基準ブランチへ統合済みです。古いmainをそのまま本番基準に戻して、既存の変更を失わないようにしています。

AGENTS.mdとCLAUDE.mdには同じ実行コマンドを記載しました。変更したソースの実CIがない場合、古い成功結果しかない場合、必要な依存先を省略した場合は、本番切替へ進めません。新しいworkerと、workerとは別に更新したverifierも対象です。実際の受入を行わないPASSファイルでは代用できません。
