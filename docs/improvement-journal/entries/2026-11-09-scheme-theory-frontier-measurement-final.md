# スキーム論の易しい命題と Frontier の取り込み（2026-11-09、最終、上限 10 ドル）

- 指標: 成功率・時間（新分野での通過数と、1枚あたりの秒数）、費用
- 仮説: [中間エントリ](2026-11-09-scheme-theory-frontier-measurement.md)と同じ。Frontier の定義を命題の側でも使えるようにすれば、スキーム論の易しい命題を Mathlib 版 24 枚（23/24）と同水準の成功率、中央値 120 秒以内で通せる。
- 変更（PR・コミット・フラグ、既定のオン/オフ）: 中間と同じ（pals-agent #74、新プロファイル `stacks-frontier-defs-4.35`、フラグ `PALS_LEAN_ALLOW_FRONTIER_STATEMENTS`、既定オフ）。測定の規則の変更は、pals の事前登録の「変更履歴」にある。合計上限 3→6→10 ドル（ユーザーの指示）と、腕 c を腕 a の残りより先にした順序（予算の見立てによる。M14 の失敗を見て決めたのではない）。
- 測定の条件: Terra（リリース既定、medium）、修復上限 6、各カード 1 回、命題固定、意味審査あり。実行 27 回（腕 a が M01〜M16 の 16 枚、腕 b が M07・M09・M14 の 3 枚、腕 c が F01〜F08 の 8 枚）。C01・C02 は予算のため未実行（分母に入れない）。他のセッションが動く機械で、開始時の 1 分ロードの中央値は 8〜12。
- 結果:

- 失敗の分類（診断コードのみ）: 失敗 11 回のうち、最終の診断が `lean.formal_harness_mismatch` または `lean.statement_mismatch` だったのは 6 回（M14 の a・b、F03、F04、F07、F08）。ほかは `lean.error`（型の不一致、未解決の目標）と `lean.synthInstanceFailed`。意味審査で `rejected` になった例はなく、成功 16 回すべて `approved`。失敗は修復上限 6 を使い切り、費用の 68%（$6.66 / $9.84）を使った。
- 信頼: F01、F02、F06 の成功は `frontier_statement` を記録。F02 は重複定義の診断（非エラー）も出た。
- Frontier の読み込み: 中間と同じ（import は温かい状態で約 +1 秒、メモリ +1.6 GB、全体の外挿はビルド約 15 時間、メモリ約 32 GB）。F 群の固定 import の閉包は 3〜480 モジュール。
- 判断:
  - 成功（A）: 腕 a は 0.75 で基準 0.85 に届かず、区間が 0.958 を含まない（低い）。腕 c は比較の基準がなく、通過数のみを書く。腕 b は 3 枚で保留。
  - 速さ（B）: 全実行の中央値は、どの腕も基準の 120 秒を超えた。Lean の検証は実時間の約 7〜10%で、時間の大半はモデルの呼び出しと修復。
  - 費用の差（F01・F02 の $0.04 と、失敗した F の $0.34〜0.71）の原因は、呼び出し回数（修復 0 回で 3 回、6 回で 16〜27 回）と出力トークンで、Frontier の有無ではない。
- 費用: 実行 27 回で $9.84、試運転 $0.12 を含めて $9.95（`gpt-5.6-terra` の単価での概算、`gpt-6.1-terra` の単価は未確認）。
- 限界・未確認: 各 1 回で分散を見ていない。腕ごとにカードの集合が違う。F の失敗 5 枚のうち、補題が組み込み済みの範囲にあったかは F04・F07 以外未確認。Lean の検証時間は下限。命題は AI（私）が書き、人手のレビューなし。Docker、`api_reconcile` 経路、pals-api の `library_profile` 受け入れ、画面での信頼レベル表示は未対応。
- 次にやること: (1) 命題の不一致が続く実行を早く打ち切る設定（#76 の `stop_on_repeated_harness_mismatch` など）の効果を、失敗した 11 枚で測る（元の費用 $6.7 が上限）。(2) F の補題が範囲外のカードの分、組み込み済みの範囲を広げる（追加 1,000 モジュールで約 14 分、有料の実行なし）。(3) C01・C02（約 $0.6）と、F 群の 2 回目（約 $2.7）。
