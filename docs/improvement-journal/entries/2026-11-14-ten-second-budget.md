# 10 秒の時間の予算表と、推論の強さを下げる 2 案の測定(2026-11-14)

- 指標: 質問から検証済みまで、および回答の表示(解説と審査まで)までの秒。10 秒目標は [pals#137](https://github.com/AtsushiHosaka/pals/issues/137)。
- 仮説: 初回で通る題に限れば、時間は「初回 Prove」「検証」「解説と審査」に集まる。推論の強さを下げれば Prove と解説が縮み、10 秒に届く。
- 測定: dev_unseen 20 題(使用済み)と generation-eval-v1 の tuning 14 題、worker の carry 経路のドライバー(API の compile は常駐 Lean で代用、往復は固定 1.1 s、負荷平均 4.7〜17)。構成は 既定(フラグなし)/ 全 T2 フラグ(hetero_par)/ cheap-first(初回 low)/ cheap-first+初回 none / 同+解説 none。各 1 回。表: `data/2026-11-14-ten-second-budget/`。

- 読み取り:
  1. 初回で通る題の「検証済みまで」は、cheap-first(別セッションの PR #129)で p50 9.3 s に入っている。しかし**表示まで**は 19.7 s で、差の 10.4 s は 検証後の「解説の待ち 4.1 + 解説の出力レビュー 2.9 + 意味審査 1.9」。クリティカルパスは 初回 Prove → 解説(Prove の完了後に始まり約 6〜7 s)→ 出力レビュー で、検証(1.9 s)ではない。
  2. 初回 none は Prove を 7.5 → 4.2 s に縮めるが、dev では初回成功が 13 → 7 に落ち、修復に回る題の時間が伸びて p50 が悪化した(負荷 17 の時間帯が混じる)。tuning では(解説 none を併せた構成)p50 12.6 → 6.5 s、≤10 s は 5 → 9。題の集合で向きが逆で、n が小さく、結論を出せない。
  3. 解説 none は解説の待ちを 4.1 → 3.1 s にしたが、p90 は 15.9 s と外れ値が出た。出力レビュー(2.8 s)は変わらない。
  4. 解説の呼び出しが 1 題あたり 2.4〜5.3 回(破棄された先行分を含む)。時間には効かず、費用の無駄。
- 判断: `PALS_T2_FIRST_EFFORT`(none/low/medium、cheap-first の初回のみ)と `PALS_EXPLAIN_EFFORT`(none/low)を既定未設定(変更なし)で実装し、測った。**どちらも有効化は勧めない**(効果が題の集合で逆、初回成功が落ちる題がある)。表示の 10 秒に届かせる残りの 10 s は、正しさを変えずには削れない。
- 提案(実装していない。利用者に見える挙動が変わる): 検証済みの証明と結論を先に表示し、解説を後から差し込む(解説の出力レビューは解説の公開前に残す)。表示の p50 が 19.7 s → 検証済みまでの 9.3 s に近づく。「検証済み」の表示の根拠は変えず、解説は審査を通ってから出す。
- 限界: n 小・1 回・負荷 4.7〜17・API の compile は代用。dev_unseen は使用済み。台帳の 8 行、費用は 7 本で約 3 ドル(1 本 1 ドル以下)。通信の影響ではなく**自分で付けた総額の上限(6 ドル)**で 1 本が途中で止まったため取り直し、止まった分は台帳に別行で残した。
