# スキーム論の質問を検証済みの回答まで通す（2026-11-14）

- 指標: 依頼どおりの命題をレビューまで通した題の数（検証済みの数ではない）。副指標は初回成功、回答完成までの時間（p50/p90）、1 題あたりの費用。
- 仮説: スキーム論の質問が通らないのは、生成が命題を弱い補題にすり替えて検証を通すため。宣言の索引や Stacks 環境の振り分けより前に、この段で起きている。
- 現状の数え方: 新しい評価の区分 `algebraic-geometry-v1`（10 題、held_out と重ならない）を、worker と同じ生成の経路で 5 題ずつ 2 回実行した（モデルは本番の役割割り当て、Lean は v4.32.0-rc1）。
- 変更: スキーム論の質問に限り、Mathlib の確認済みの名前の案内をプロンプトに足し、定理文にスキームの語彙が無い候補を検証前に失敗にする（pals-agent）。信頼の水準を `ProofRunResult.library_trust` に出す。
- 結果（各 n=1）: 依頼どおり 5/10 → 8/10。Lean が通った数は 9/10 のまま。初回成功 5 → 3。p50 169 → 85 秒、p90 353 → 387 秒。費用 0.58 → 0.74 ドル（修復の多い 2 題が 0.50 ドルを占め、残り 8 題は 1 題あたり約 0.03 ドル）。
- 切り分け: 依頼どおり 5→8 のうち、検査が発火したのは連結性と高次順像の 2 題だけ。ほかの改善は案内かゆらぎで、切り分けていない。
- 判断: 採用（命題のすり替えを減らす一般的な修正として）。ただし件数の差は n=1 では誤差の範囲でもありうる。
- うまくいかなかったこと: 連結性の題は、語彙検査を通る部分命題（コンパクト性 ∧ 冪等元の補題）を作り、修復 6 回、771 秒で、レビューが却下した。語彙検査は部分命題を弾けない。高次順像の題は Mathlib に概念が無く、失敗した（修正前は、コメントだけのファイルが「検証済み」になっていた）。
- 限界・未確認: Stacks 用の検証環境は手元に無く、起動と import の時間は測っていない。意味レビューはモデルによる判定。修正前後の負荷は同程度（1 分平均 4〜8）だが同一ではない。
- 次にやること: 質問から検証環境を選ぶ振り分け（配備を伴うので案）、部分命題の検出（固定した形式化）、案内に載せる API の拡充。
