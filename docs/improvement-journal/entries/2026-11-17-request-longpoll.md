# requestの長いポーリングによる状態取得

#380に関連し、APIの確定通知を画面へ届ける待ち時間の短縮を試みた。[Web PR #84](https://github.com/AtsushiHosaka/pals-webfront/pull/84)の最終headは94436a147b9ba8b6606f5189e8224a2e994bea5e、mergeは6dea87ed9af806ddecc124206c416a8dae4c450f。

requestごとに状態を反映し、最大4枠、10秒待機、20秒deadline、非対応時の従来pollを維持する。独立レビューで認証待ちの取消後に枠が残る不備を発見し、即時返却と遅延fetchの抑止で修正した。旧版で回帰が失敗し、修正版で成功した。最終headのCIとローカル全回帰2,172件は成功した。途中のfixture不備と原因未確定の認証テスト単発失敗はPRの検証記録へ保持した。

実ブラウザ50試行の性能、実Leanから画面までの時間、既存job取得との経路統合は未確認。技術テスト件数を製品の成功率へ加算しない。本番配備は未実施で、10秒目標全体は未完了。
