# 意味の審査で不合格の依頼を、新しいジョブで 1 回だけ作り直す（実装）（2026-11-14）

- 指標: 意味の審査で不合格になった依頼が、回答まで到達する割合。誤った回答を通さないこと。追加の費用・時間。
- 変更: [pals-api#108](https://github.com/AtsushiHosaka/pals-api/pull/108)（マージ済み、既定 off の `PALS_SEMANTIC_REVIEW_REFORMALIZE_ENABLED`、本番へは未配備）。承認された「ジョブを形式化の段へ戻す」設計は、`proof_verification_candidates` の `UNIQUE (proof_job_id)` と、審査の証跡の `ON DELETE RESTRICT` の FK のため、証跡を失うか DB 制約の変更が要る。代わりに、PFR-015（反例の検証失敗 → 主張を新ジョブで証明）と同じ形で、**依頼に新しいジョブを 1 つ作らせる**形にした。不合格のジョブと審査の証跡は不変。作り直したジョブも Lean と意味の審査の両方を最初から通る。
- 条件: 上限 1 回（定数）、最初の 1 件のリンクだけが対象（後続ジョブ・ゲスト・dsp 以外は対象外）、最初のジョブの実行が 600 秒以内（未検証の期限が有効なら期限 − 150 秒以内）。2 回目の不合格は従来どおり終端。表示（進行・最終の文言）は変えない。DB 移行なし。agent 側のフラグは不要と判断（却下理由を渡しても改善しないことを測定済み）。
- 測定: API を通した端から端までの測定はしていない。実 PostgreSQL の統合テスト 3 件（作り直しが 1 回だけ起き 2 回目は終端、フラグ off・実行が長い依頼は従来どおり、反例失敗の後続ジョブは作り直さない）。効果は [pals-agent#137](https://github.com/AtsushiHosaka/pals-agent/pull/137) の測定（作り直すだけで 8/8 が再審査で承認、約 100 秒、約 US$0.045 / 件）からの推定。全工程の回帰セットでは 11/12 が返り、却下は 1 件だった。
- 判断: 採用（既定 off）。独立レビューの指摘（3 つ目のジョブ、時間の基準、審査の文言、ゲスト）を反映済み。
- 限界・未確認: 本番の却下の分布と率は未確認で、追加の費用は却下された依頼の分だけ。画面は jobId が変わると経過時間を数え直す（表示の文言は変わらない）。実際の端から端までの効果は、フラグを有効にした環境での測定が要る。
- 次にやること: フラグを有効にした環境（ローカルの API + worker）で、却下の実例を通して回答が返る割合と費用・時間を測る。
- 出典: pals-api#108、pals-agent#137、[契約案](../../semantic-review-rejection-contract-2026-11-14.md)。
