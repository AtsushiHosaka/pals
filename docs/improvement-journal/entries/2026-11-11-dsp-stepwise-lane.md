### 報告された問題（|μ−m| ≤ σ）

3腕とも失敗: base 641 s（修復6）、`nd_k2` 514 s（修復6）、stepwise 944 s（修復6、モデル呼び出し39、US$0.43）。stepwise のレーン内は 409 s、モデル呼び出し16、コンパイル24で、骨格を作り、再スケッチを1回して、ステップが残り、通常経路に戻った。

- 手書きでは約35行の補題が要ったステップ（「中央値が E|X−c| を最小にする」）は、**モデルが見つけた**: 修復2回を経て（モデル3呼び出し、116 s、コンパイル5）通った。平均の下界のステップも修復で通り、`0 ≤ ∫|X−μ|` は自動化で閉じた。
- 落ちたのは、モデルが `E|X−μ| ≤ σ` を細かく分けた2ステップ（`(∫|X−μ|)² ≤ ∫(X−μ)²` と、それが分散に等しいこと）。どちらも3回の試行（Sketch の1回目と再スケッチの後）で通らなかった。分け方がモデルの選択で、ここが詰まった。
- 定理文は固定でシステムが挿入するので、忠実さは構造上保たれる（弱めや仮定の落としは起こり得ない）。ステップの主張も、元の人間の証明どおり（中央値の最小性、平均の下界、分散への帰着）で、弱めた主張は見当たらない。

### ステップ別の内訳（再実行後、レーンが走った15回＝14題＋`mv_foundation…`。最終骨格のステップ計47）

### 忠実さ

固定の定理文がある題は構造上保たれる。固定文がない題で最終ファイルを読んだのは `seed-rank_nullity`（斜体上の有限次元、仮定の落としなし）と `pq-compact-hausdorff…`（コンパクト＋ハウスドルフ＋連続な全単射、逆写像の連続性）の2題だけ。どちらも弱めはない。残りは読んでいない（未判定）。

## なぜ遅いか

- stepwise の時間の内訳（p50 級の題）は、Sketch 7〜41 s、骨格の検査 6〜20 s、Stage 0（モデルなし）8〜30 s、ステップ 17〜40 s。**固定の前処理（Sketch＋骨格検査＋Stage 0）だけで 21〜60 s** かかり、`nd_k2` は全体で 13〜74 s。routine の題でも、Stage 0 が閉じて終わる場合でも、前処理だけで 21〜23 s。
- 自動化の7本の `first |` を各ステップで走らせるため、閉じない場合に1ステップ当たり約10〜15 s（負荷下）かかる。
- 多段で落ちる題では、ステップごとの修復が積み上がり（`scheme-M13` は 16 呼び出し、`seed-absolute_value…` は 14）、再スケッチと通常経路への復帰で全体が長くなる。p90 の 740 s がこれ。
- 初回で全体が通った割合は stepwise が最も高い（10/14 対 `nd_k2` 9/14、base 6/14）。ただし検出できる差ではなく、時間の悪化で相殺される。

## 測定の中の不具合と訂正（最初の測定は無効）

最初の実行（b1〜b5）で、stepwise は 14 回中 9 回、骨格が解析できず（`skeleton_invalid`、コンパイル0）、通常経路に戻っていた。原因はレーンの解析: 固定の定理文がない題でモデルが自分の定理の下に書いた区切り行を読めない／import・open・universe を含み `:= by` で終わる固定文を扱えない。修正して（赤→緑のテスト、PR #112 の2つ目のコミット）、その9題を stepwise 腕のみ再実行した（c1・c2）。**上の表は、その再実行と、無効でなかった実行を使ったもの。** 無効だった実行の費用はセッション合計に入っている（約US$1.1）。

## 副産物: 既存の不具合（レーンとは別、未修正）

結論が行頭の `|…|` で始まる定理文を、`lean_source_policy._signature`（pals-agent）が「パターンマッチの分岐」と読み違え、`statement_reference` が型を落として `: := sorry` にする。最終検査が `lean.statement_mismatch` で落ちる。報告された問題の定理文は、結論を `:` の次の行に置くと落ち、同じ行に置くと通った（同一の組み立て済みファイルで 1/2）。**この測定の題は結論を `:` と同じ行に置いたので影響を受けていない。** 本番で報告された問題が返らなかった原因の候補だが、本番の記録は見ていないので未確認。base の経路でも起きる。別 Issue／別 PR で直す。

## 判断

- フラグは既定 off のまま。マージしない（ドラフト）。このレーンは、時間の目標（大学1年 10 s、学部 30 s）に近づけるどころか、`nd_k2` より遅い（p=0.043）。
- 報告された問題は、3腕とも失敗。stepwise は、手書きで難しかった補題を実モデルが見つけられることを示したが、モデルが選ぶ分解が悪いと詰まる。
- 次に試す価値があるもの: (1) 前処理を削る（Stage 0 を骨格検査と並列に、または骨格に頼らず先頭の候補と競争）。(2) 再スケッチではなく、落ちたステップを主張ごとモデルに分割させない。(3) 「期限で未検証の途中経過を返す」案（PR #112 の本文）は、レーンの成否と独立に価値がある。(4) 上の `|…|` の不具合の確認と修正（本番の失敗の原因なら、レーンより先に効く）。
