# x² の検証結果キャッシュ（2026-11-08）

- 指標: 時間（x² の連続性カード、22〜24秒の短縮）
- 背景: x² の連続性は決定論的テンプレート経路で、モデル呼び出し0。残りの時間は検証・審査・説明。線形ジョブ終端の待ちは、説明 failed とジョブ failed/canceled の経路だけで、成功した x² ジョブの主因ではない（`proof_explanations.py:366` の `on_explanation_completed` が `wakeup.set` を呼ぶ）。
- 変更: pals-agent #80（許可リスト52本との完全一致だけを対象にした検証器のプロセス内キャッシュ。`PALS_VERIFIER_RESULT_CACHE_SHADOW`・`..._ENABLED`、既定オフ、成功のみ保存）、#81（背景再検証 `..._REVALIDATE`、既定オフ、ENABLED 時は必須）。repo の方針「検証結果をキャッシュしない」（`docs/lean-acceleration-2026-10-28.md:31-33`）を、x² テンプレートに限って変える（ユーザー承認、まず影の実行から）。
- 測定の条件: ローカル、固定版 Lean 4.32.0-rc1、実 Lean で許可リストのうち4本（変数 x、t、y、s）。`lake` は未実行。
- 結果: 初回コンパイル 17.5〜21.5秒、反復 17.4〜20.5秒（中央値 17.7〜18.5秒）。キャッシュ命中は p50 1.3ms、p95 1.6ms、最大 1.9ms（n=32）。命中はほぼ通信と TLS の時間。28項目の期待動作がすべて通過。背景再検証は、EVERY=2 で再検証のコンパイル 18.0秒、一致、その間の命中は 1.4〜3.3ms。改ざん（テスト専用）では、改ざんされた成功が先に配信され（2.6ms）、背景の実 Lean が9.2秒で拒否し、`revalidation_mismatch` と ERROR、以後の配信停止。
- 判断: 本番配備はまだしない。本番に載せるには、再 admission（全 Recipe、admitted 102件、検索公開20件）を含む release にまとめる必要がある見込み。導入順は、影の実行、カウンタの確認、有効化＋再検証。
- 費用: 金額の効果はほぼゼロ（計算ホストは固定費 月138.76ドル）。価値は待ち時間で、本番の温のコンパイル時間（約10〜13秒）が全体の約45〜55%。
- 限界・未確認: 本番・AWS・Linux の隔離（landlock・seccomp・cgroup）、`lake env`、冷たい状態（cold）、許可リストの残り48本、同時要求、再検証中の 503（最大 約0.4%〜4%程度の稼働率、N=20、日500〜5,000件）、API の再試行吸収。x² 専用であり、他の命題には効かない。
