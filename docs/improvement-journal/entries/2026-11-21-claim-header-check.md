# 複数行 have の主張見出しの検査を main へ移植し、旧新を測った（2026-11-21）

[#232](https://github.com/AtsushiHosaka/pals/issues/232)（Lean パネルの行ごとの説明）の生成側の対応として、pals-agent#50 の「複数行 `have` の主張見出しを同じ節で引用させる」検査だけを、seq31 の統合先である `main` へ手で移植した（[pals-agent#152](https://github.com/AtsushiHosaka/pals-agent/pull/152)）。#50 の他の変更は移植していない。

## 仮説
説明の書き手が、複数行 `have` の最後の tactic だけを引用して、主張の見出し行を飛ばすことがある。見出しの引用を必須にし、不足なら既存の再試行へ回せば、その行の説明の欠落が減る。

## 測定
公開の合成6題（見出し 22 個）、`gpt-6-luna` low、旧（検査なし）と新（検査あり）を各 2 反復、本番と同じ書き手 → QA → 修正1回の経路。2026-11-21（JST）。費用は予約レートでの推計。

| 指標 | 旧 | 新 |
|---|---|---|
| 回答まで到達 | 12/12 | 12/12 |
| 所要時間（平均、中央値、最大） | 14.1 s、13.85 s、23.5 s | 13.9 s、11.95 s、29.1 s |
| 30 秒以内 | 12/12 | 12/12 |
| 見出し 22 個のうち欠けたもの | 0 | 0 |
| 引用に入らないコード行 | 35/164 | 33/164 |
| 推計費用 | 0.0281 USD | 0.0318 USD |

## 結果と判断
- **検査は一度も作動しなかった。** 旧 arm でも、Luna low は 22 個すべての見出しを引用した。この6題では、改善も悪化も測れていない。差は偶然の範囲で、効果とは読まない。
- 保存済みの実生成9件（ローカル）では、コード行の 5〜18 行が引用に入らず、その原因は見出しではなく、1 行の見出しの下の `calc` ブロックなどだった。この検査では直らない。案 B（節の間でも行を飛ばさない指示）の評価が要る。
- 時間・成功率の悪化は確認できなかった（最大時間は 23.5 秒から 29.1 秒に増えたが、差は偶然の範囲で、検査は一度も作動しなかった）。このため `main` へマージする（既定で有効。見出しを持たない Lean ではプロンプトも挙動も変わらない）。効果は確認していない。

## 失敗した試行
- 1 回目の実行は、2 試行の後、OpenAI への要求が10分以上応答せず止まった（要求に時間切れを付けていなかった）。中止、推計 0.0053 USD。
- 2 回目は、時間切れの指定が `deadline` と対だと知らず、24 試行が即時に `ValueError`。費用 0。
- 3 回目が上の結果。いずれも `pals-agent/testdata/explanation-claim-headers-v1/results/` に残した。

合計の推計費用は約 0.065 USD。`held_out`、利用者の質問、過去の6題は使っていない。
