# seq30のセッション更新

[pals#386](https://github.com/AtsushiHosaka/pals/issues/386#issuecomment-6872271714)の切り替え前の問題を記録する。現在ログイン済みのChromeで通常の画面操作による更新を1回行うことは、オーナーが承認し、実行済みである。更新後もIDトークンは15分、アクセストークンは30分で失効する。静的な書き出しファイルだけでは、準備と切り替えをまたぐ有効期間を確保できない。

## 実装と承認の範囲

親`8bfb43a`の[post-requestブラウザーヘルパー](../pals-scripts/release-post-request-browser.cjs)は認証先への通信をすべて拒否していた。修正では、製品が通常行う更新要求だけを一時的なヘッドレスブラウザーから通す。実装の準備と、認証先へ実際に更新要求を送る許可は別である。2026-11-14にオーナーは、PR #390の手順をseq30限定で実セッションに使うことを別途承認した。[判断の記録](https://github.com/AtsushiHosaka/pals/issues/386#issuecomment-6872609209)に対象と条件を残した。Chromeでの1回の操作承認や、セッション書き出しの承認を広げたものではなく、この経路に対する明示的な承認である。

[読み取り専用ガード](../pals-scripts/release-cognito-refresh-policy.py)がSTSのアカウントとCognitoのクライアント設定を新たに読み取る。秘密を持たない公開クライアントで、更新トークンのローテーションが未設定または無効、かつ`ALLOW_REFRESH_TOKEN_AUTH`が有効な場合に限る。アカウントとリージョンは、固定した本番SSM契約の各役割で一致している必要がある。[AWSの公式仕様](https://docs.aws.amazon.com/cognito/latest/developerguide/amazon-cognito-user-pools-using-the-refresh-token.html)でも、`REFRESH_TOKEN_AUTH`はローテーション有効時には使えない。

転送するのは製品自身が送る`InitiateAuth`の`REFRESH_TOKEN_AUTH`だけで、送信先・パス・ヘッダー・本文のキー・クライアント・元の更新トークンを照合する。デバイスキーは保存値と一致するもの、または保存値がない場合のSDKのnullだけを認める。リダイレクトは追わず、一時的なブラウザーの外へ新しい認証情報を書き戻さない。[受け入れ確認](../pals-scripts/release-acceptance-browser.cjs)にも同じ制約を適用した。

上限はブラウザーのコンテキストごとに1回である。post-requestと受け入れ確認は別のコンテキストを使い、通信の復旧でヘルパーを起動し直した場合にも別の上限になる。リリース全体で認証先への呼び出しを1回にする制約ではない。トークンの出力、手動の認証API要求、Cognitoの設定変更は行わず、既存の有料質問の予算・重複防止・API経路も変更しない。

## 確認できたことと残る確認

固定入力と代用品を使う回帰テストで、厳密な要求の照合、更新回数、リダイレクト拒否、認証先の設定拒否を確認した。最終版の`bash pals-scripts/tests/release-acceptance.sh`はPython209件とNode16件を実行して合格した。Pythonの既存3件のスキップは残しており、未実行の境界を合格とは扱わない。ブラウザー用の5件には、期限切れのIDトークンから通常の更新を経て新しい製品リクエストの認証情報を得る代用テストを含む。この1件は修正前の`8bfb43a`では失敗し、修正後には合格した。独立レビューで見つかった再読み込み時の上書きも修正し、更新済みのブラウザー内の値を保持する回帰テストを追加した。単体テストの件数を製品や認証の成功率には数えない。

実環境では、新しい読み取り専用ガードを1回実行し、`readonly_refresh_policy_verified`を得た。実アカウントとクライアント設定の確認だけで、更新要求や質問は送っていない。品質台帳の`2026-11-14-seq30-refresh-readonly-policy`はこの技術試行1回を数え、認証の成功や数学的な回答の成功を表さない。

実際のヘッドレスブラウザーからのCognito更新と、切り替え後の本番回答・保存・描画・再読み込みは未確認である。テストの合格を実行承認や本番受け入れの代わりにはしない。認証情報・質問・回答の内容はこの記録へ載せない。
