# リリース制御のコード統合と参照の保全

2026年11月9日、ユーザーはInfra #110、親の参照更新、親 #310を、必須CIを確認して順に統合することを承認しました。本番切替、IAM・通知設定、ローカルDB権限、Agent #85の統合は承認範囲に含みません。[判断記録](https://github.com/AtsushiHosaka/pals/issues/312)

## 最終レビューで見つかった問題

親PRは、APIとワーカーの参照を本番系統の候補へ変更していました。その候補は、親mainにあるすべての機能を含んでいませんでした。APIでは数式を含むタイトルの変換、添付解析前の予算制御、認証鍵の取得制限が外れます。ワーカーでも図・品質イベントなどの実装が欠けます。今回の二参照の更新だけを確認するレビューでは、この差分を見落としていました。

本番系統の候補を保持することと、開発mainの既存機能を保持することは別の確認です。現在の本番の挙動が、今回のコード統合で変わったことを意味しません。

## 残る受入と本番適用

今回の統合はソースと実行ゲートの整備です。選択した親ソースを、そのまま署名・配備できる候補とは扱いません。現在の本番候補との互換性、正確なsource/image、API修正の合流、ローカル実DB・実Lean・実モデルでの完了・保存・表示・再読込、復旧の実検証が残ります。

ローカル二列の権限追加も引き続き承認待ちです。現在Chromeの本番一件は配備後の別の受入で、まだ実施していません。通知制御の実AWSでの期限切れ・配送検証、公開停止前のジョブ確認の接続も未完了です。[機能と進行の正本](https://github.com/AtsushiHosaka/pals/issues/309)
