数式span、正規化済みscript、Unicodeの位置は保護したままです。事前判定と本処理は、それぞれ走査位置を前に進めます。括弧を含む2000個の積でも出力を確認しました。一般のMarkdownの曖昧さをすべて解決する変更ではありません。Next.jsとOrigin制御、MathLive、設定、ロゴ、共有操作とOGのコードは変更していません。

修正後は同じ3ファイルの関連99件、Webのlint、型検査、差分検査が成功しました。前回の星・語間の積・scriptに加え、外側斜体と括弧付き積、通常の独立した強調、Greek・astral文字、前後のUnicode空白、三重強調を確認しています。これらはソフトウェアの回帰テストで、品質台帳へは追加していません。

修正コミットと親の参照更新は対応PRに記録します。公開後の独立レビューは、この追加修正の範囲で行います。本番配備や実ブラウザの受入を示す結果ではありません。

Web `4b3db41`では、`*A ***continuous*(on R)** B*`が`*A continuous*(on R) B`となり、`*A ***term*[remark]** B*`でも星が残りました。外側斜体を優先する判定が、内側の強調を閉じる処理にも適用されていました。追加した変換・匿名表示・所有者プレビューの12件は、修正前にすべて失敗しています。

[Web #55](https://github.com/AtsushiHosaka/pals-webfront/pull/55)の`831c17bc`と同じ限定修正を`efff97b`へ引き継ぎました。直近の開始区切りが外側の開始位置に一致するときだけ、外側斜体の判定を適用します。内側の強調は従来の対応付けで閉じます。新たに追加するのはスタック末尾の一定時間の参照だけで、走査方法は変えていません。

修正後は同じ3ファイルの関連111件、Webのlint、型検査、差分検査が成功しました。入れ子の強調に括弧付きの積を組み合わせた例、astral文字、数式内のscriptも確認しています。匿名表示は保存済みデータを取得して表示する経路を通し、所有者プレビューは保存済みsnapshotを取得し、新しいプレビューを要求しないことを確認しました。前回までの積・強調・数式保護のテストも保持しています。

## 独立レビューで確認した内側強調の積

`efff97b`の公開後の独立レビューでは、関連111件とlint・型検査は成功したものの、内側の三重強調に積を置くと数学記号が消える回帰を確認しました。`*A ***Prove f*(g+h)*k is continuous*** B*`と、`(f+g)*(h+k)`を使う同形の例が対象です。これらは`4b3db41`では積を保持していたため、レビュー結果はFAILとしています。

修正`391c7aa`では、既存の事前走査で内側の複数starの開始・終了を対応付けます。元の奇数幅の開始区切りを、同じ幅の終了区切りで一度に閉じる場合だけ、その内側の積を保護します。途中で一部を消費した開始区切りは保護対象にしません。外側斜体の既存判定が有効な場合に限定して適用し、最初の2件の入れ子も正しく閉じます。走査中に各区切りをスタックへ一度追加・除去するため、starごとに残りの文字列を検索する処理は増やしていません。

このレビューから追加した8件は、`efff97b`で全件失敗しました。修正後は同じ3ファイルの関連119件、lint、型検査、差分検査が成功しています。匿名取得から表示する経路と所有者の保存済みプレビューを両方確認し、内側に2000個の積を置く例も追加しました。119件は前回の111件を含みます。前の成功だけで修正完了とはせず、今回の失敗と再実行もこの記録へ残します。

変更するファイルと配備の範囲は前節と同じです。品質台帳には追加していません。再push後の独立レビュー結果と親の正確な参照は、対応PRに追記します。
