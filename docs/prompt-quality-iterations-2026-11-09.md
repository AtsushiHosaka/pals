# 説明プロンプトの実測比較

2案を実モデルで比較しましたが、今回の3題では改善を確認できませんでした。v2は公開レビューを通らない試行があり、v3は全試行で説明を返せたものの、主指標のわかりやすさがわずかに下がっています。両案とも本番への採用は保留します。[Issue #316](https://github.com/AtsushiHosaka/pals/issues/316)に進行を記録しています。

## 条件と対象範囲

大学学部生向けの日本語で、二乗関数の連続性、絶対値の微分不能性、√2の無理性を比較しました。各回で基準条件も生成し直し、各条件を2回ずつ実行しました。2案で24試行です。修正生成や公開レビューは同じ試行内の処理であり、独立した問題数には数えません。

過去に検証された3題のLeanソースを読み取り、元の評価記録のハッシュと完全一致することを確認しました。生成と公開レビューには、実運用のfactory、構文・出典検証、1回のレビュー修正ループを使用しています。モデルは両方とも`gpt-6-luna`、独立採点は`gpt-5.4-2026-03-05`です。採点器には案の名前や公開レビューの判断を渡していません。参考解答は採点だけに使いました。

実装、入力、モデル設定、採点基準、表示処理は固定し、追加する説明方針だけを変えました。v2は推論と理由を近くに置き、矛盾の重複を避け、仮定の必要性を正しく説明する指示です。v2の結果を受け、v3では指示を短くしました。各問題・試行で実行順を入れ替え、変更前後を交互に実行しました。

これは説明の生成段階の実験です。新しい証明リクエストやLeanコンパイルは行っていません。既存のカタログ回答や固定テンプレートの改善、証明フロー全体の成功率も測っていません。両条件に実際のAPIの本文変換を使ったため、構造化説明のconclusionを表示本文から落とす当時の処理も同一です。その表示処理の問題は別に追跡します。

生成・レビュー処理の平均は、v2の変更前15.326095秒、v2は18.937627秒、v3の変更前15.4830365秒、v3は19.0517493秒です。各6試行で、v2の失敗した試行も含み、独立採点の時間は含みません。証明フロー全体や画面への応答時間とは分けて扱います。

欠測を含む全6試行のわかりやすさの差の範囲は、v2で−0.16833〜−0.00167です。これは未知の得点を0〜1の範囲に置いた欠測の範囲であり、信頼区間ではありません。問題を独立単位とする保守的な95%区間は、全指標で−1〜＋1です。3題はすでに調整に使った問題であり、未知の検証用問題ではありません。小さな採点差を一般的な改善と解釈せず、今後は別の問題の追加と人による採点の確認も行います。
