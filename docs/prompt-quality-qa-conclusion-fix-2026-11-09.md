# QA誤拒否・結論表示の修正と同条件の再評価

QAの拒否理由を実際の文と数学的条件に結び付け、APIで結論を落とす処理を修正しました。同じ6題を各2回、修正前後で生成し直した24試行では、回答完了が10/12から12/12になりました。採点できた10組を問題ごとに等重みで比べると、わかりやすさは＋0.50pt、簡潔さは−1.33ptです。改善と悪化を両方残します。

これは説明生成・QA・APIの本文変換を実コードで動かした再生評価です。本番への配備と実画面の受入確認は行っていません。進行の正本は[Issue #319](https://github.com/AtsushiHosaka/pals/issues/319)です。

## 修正内容

QAには、拒否理由で対象のフィールドと実在する文を示し、どの数学的条件や表示要件に反するか説明するよう指示しました。検証済みの補題の内容を通常の数学で説明すること、背理法の仮定の下で議論すること、同じ意味の日本語で結論を述べることを認めます。誤った式・条件の追加・存在しない引用・実際の結論欠落の拒否は維持します。拒否を承認へ変換する処理、追加の多数決、モデル変更は入れていません。

APIには、構造化回答のoverviewとsectionsの後にconclusionを追加する既存の修正ce5cd2fを使いました。後続のAPI変更を古い版で置き換えていません。新しい回帰テストは[API PR #96](https://github.com/AtsushiHosaka/pals-api/pull/96)、QAの変更は[Agent PR #88](https://github.com/AtsushiHosaka/pals-agent/pull/88)です。

API本体と評価用の変換処理は、実際の保存済み回答24件と境界条件8件で一致しました。任意項目・段落順・長さ上限の単体検査と、専用の実PostgreSQLを使う保存・再取得・一覧・次の会話履歴の確認も通っています。これらはローカルの検証で、Cognitoや本番画面を通った証拠ではありません。

## 失敗も保持した固定QA検証

同じ正例6件と負例7件を、各案につき修正前後へ1回ずつ渡しました。負例は、誤った因子評価、左右極限の誤計算、偶奇推論の逆転、共通添字の誤り、大小の逆転、階乗に1を足した数そのものを素数とする誤り、具体的結論の欠落です。期待判定や参考理由はQAモデルに渡していません。

最初の案は、絶対値の左右の差商を正しく説明した文を、Leanに中間計算の行がないという理由で拒否しました。2案目はこれを承認しましたが、素数の存在を述べる日本語を、同じ意味のLean命題と対応しないとして拒否しました。最終案はこの2点を明示し、正例6/6・負例7/7が期待どおりでした。修正前は3回とも、具体的結論のない負例を誤承認しました。2回目の修正前では、自然数0の場合の補足にも根拠のない拒否がありました。

これらは同じ13入力の反復です。案をまとめて独立した39題の精度にはしません。最終案の1回の通過だけで、誤拒否が一般に解消したとも断定しません。先の失敗と最終案の成功は別の記録として保持します。

## 6題の比較条件

問題は、二乗関数の連続性、絶対値の原点での微分不可能性、√2の無理性、数列の極限の一意性、正の導関数からの単射性、任意の上限を超える素数です。前回と同じ問題文・参考解答・Leanソースを固定しました。追加3題のローカル検証と、既存3題の本番由来の証跡は、それぞれの出典を保持しています。新しいPALS証明リクエストは0件です。

両条件でv4の生成指示を使い、生成・公開レビューはgpt-6-luna、独立採点はgpt-5.4-2026-03-05です。言語・ルーブリック・役割・クライアント・2反復・試行順・呼出し上限・制限時間も固定しました。6題すべてで、初期生成と修正生成の実際のプロンプトが同じであることを確認しています。外部モデル自体の不変性や乱数の一致は保証していません。

実装の変更はQAの指示とAPIの結論追加です。両者を合わせた効果を調べる比較であり、個別の寄与を分離する実験ではありません。実際に異なるソースと設定のハッシュを保持し、元の厳格なプロンプト比較器の条件は緩めていません。別プロセスと別の追記式ジャーナルを使い、モジュールキャッシュの混在や結果不明の再送を防ぎました。

## 採点が下がった回答の点検

簡潔さが下がった5組と、わかりやすさが下がった1組を、実際の文と照合しました。
