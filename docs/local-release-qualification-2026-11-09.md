# ローカルでのリリース前検証

2026年11月9日、修正版APIとWeb、実PostgreSQL、実Lean、実モデルを使い、質問の送信から回答の保存・再表示までを検証した。最初の試行はLeanの隔離処理を開始できず、受入は不合格となった。この修正を本番には配備していない。

| 項目 | 実測・確認結果 |
| --- | --- |
| API | `b7191f347f69379b13cba32b06a38c8eefd59a35` の公開済み不変イメージ |
| Web | `09cf9ed914e681df7da6255fa813e4a47f6ff033`、ローカル接続用の公開設定で構築 |
| ワーカー | `b27f1d8292391567a2ca15f103eb08b18dc016c4` の既存不変イメージ |
| Lean検証器 | `189b44378e6e63e5ab7c92d9c5b7d6507acd80f0` の既存不変イメージ |
| 題材 | 数列 `1/(n+1)` が0へ収束することのε–N定義による証明 |
| 指定 | GPT-6.1 Terra、推論量Medium、英語 |
| 送信 | 一件。失敗後の再送なし |
| 終了状態 | `failed / lean_verification_failed`、修正6回・試行7回、`repair_budget_exhausted` |
| APIが返した分類 | `lean.compile_error`。実際は検証器の隔離機能が利用不能だった |
| 原因の確認 | 本番と同じ設定の検証器から `lean.sandbox_setup_failed`。AMD64エミュレーションではLandlockのABI照会が `ENOSYS / errno 38`、同じVMのネイティブARM64環境ではABI 10を返した |
| モデル利用 | 実呼び出し19件、保存された価格表による保守的な費用見積もり0.141154米ドル |
| 全体予算 | 全モデル呼び出しを合計し、送信前に0.90米ドルで制限 |

費用は依頼側の利用記録2件・0.003635ドルと、形式証明ジョブ側17件・0.137519ドルの合計で、通信制御側の集計とも一致した。請求書の確定額ではない。依頼側の表だけを数えると形式証明の利用を見落とすため、両方を照合した。

実モデルから実Lean検証器への経路は通ったが、隔離処理の失敗により証明のコンパイルを開始できなかった。数学的な証明能力の判定ではない。検証器のHTTP層が基盤の失敗を一般のコンパイルエラーとして返したため、モデルの修正を6回繰り返した。後続の有料検証前には、必須の隔離処理を維持した検証器でコンパイルの事前確認を行う。

回答の完了・保存・描画・再読込には到達していない。結論保持の実DB回帰テストやWebの単体テストとは別の結果として記録する。不合格の記録を過去の成功や手動のPASS値で置き換えず、候補の本番切替を止める。ローカルでは同じソース・Lean版・Mathlib版のARM64検証器を準備し、本番AMD64イメージとは異なる境界として明記する。本番のLean実行可否を示す結果でもない。

ローカルでは認証とキューを代用し、専用DBの初期化権限を使った。本番ワーカーにローカル通信制御ツールがないため、別コンテナで通信を制限した。実モデルへの通信には予算制限用の中継を使い、実際の提供元へ転送した。これらの設定・コード・イメージを検証対象に固定する。本番の認証・通信や無停止切替を確認した証拠にはならない。

同日0時23分JST時点で、本番の既存七コンテナとALB接続先は正常だった。一方、別チャットのワーカー更新がリリース所有権を保持していたため、このチャットからの本番操作は保留した。承認されたChromeアカウントからの本番一件は、まだ送信していない。
