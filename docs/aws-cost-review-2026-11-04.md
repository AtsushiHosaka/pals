# AWS費用の調査（2026年11月4日）

11月4日23時台JSTにGmail、Cost Explorer、AWS Budgets、稼働資源、CloudWatchを読み取り確認した。PALSの11月実額は52.672ドル、AWS Budgetsの月末予測は409.743ドルだった。100ドルは通知用の予算額であり、今回確認した設定が支出を100ドルで止めることは確認していない。

費用増加の中心は、10月30日から稼働したEC2とAurora、それらを支えるネットワークである。外部のOpenAI API請求は、このAWS費用に含めていない。モデル原価やプランの採算は、別途突き合わせる必要がある。

担当はCodex、進行管理は[#239](https://github.com/AtsushiHosaka/pals/issues/239)。担当チャットは[このCodexチャット](codex://threads/01a1a6ef-927b-7d72-b689-5c442ada7af7)。オーナーは同日、口座ID、アドレス、ホスト、利用者の内容を除いた費用の公開を承認した。元メールやAWSの生データは公開しない。

## 現在も続く費用と、すでに止まった費用

現行EC2は`r8a.large`と`t4g.medium`の2台。11月3日は各24時間で、合計5.66208ドルだった。この料金のまま30日間動かす場合は169.8624ドルとなる。これは実績単価による計算であり、将来の請求予測ではない。

Aurora PostgreSQL 16.15は最小0.5、最大2 ACUだった。現在の最小値では0 ACUへの自動休止は使えない。[AWSの公式説明](https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-serverless-v2-auto-pause.html)では、対応版で最小0 ACUとし、ユーザー接続のない期間を設ける必要がある。11月3日の使用量は25.86624999 ACU時、費用は3.8799375ドル。CloudWatchの同日の平均は約1.07777 ACUで、24倍すると請求使用量とほぼ一致した。最大2 ACUへの到達も記録されている。

11月1日のRDS集計は現行DBの容量メトリクスだけでは説明できない。CloudTrailには一時的な互換性確認用DBを11月2日19時41分JSTに削除した記録があった。ただし請求を資源ID別に取得していないため、差額全体をそのDBへ厳密には帰属していない。

Interface Endpointは今回の確認時点ですでに存在せず、Gateway型のS3 Endpointだけが2件あった。Endpoint時間の課金は11月1日2.016ドル、11月2日0.84ドル、11月3日はなし。過去のEndpoint費用を今後も続く固定費へ含めたり、同じ削除をもう一度提案したりしない。

NAT Gatewayは11月3日に時間料金1.488ドル、データ料金約0.0122ドルだった。時間料金が大部分で、通信量だけを減らしても固定分は下がらない。公開IPv4は同日0.36ドル、ALBの時間料金は0.5832ドル、gp3は0.384ドルだった。

## 削減の優先順位

| 順序 | 対応案 | 見積もりの根拠と制約 |
|---|---|---|
| 1 | Auroraの0 ACU・自動休止について、現行仕様と適用差を解消する | 観測単価は0.15ドル/ACU時。0.5 ACUの床だけで30日54ドル相当。全時間休止できた場合の床部分の上限であり、実際の節約額ではない。接続や定期ポーリングが休止を妨げないか、復帰時間が許容できるかを実測する |
| 2 | 計算ホストのCPU・メモリ・Lean同時実行を測り、必要容量を選び直す | 現行r8a.largeは30日138.7584ドル相当。小さい型へ変えられるとはまだ言えない。正しさ、メモリ、待ち時間、並列数を保って比較する |
| 3 | NATとプライベート接続の構成を比較する | NATの時間料金は30日44.64ドル相当。Endpointを戻す案もAZ数・サービス数・時間料金を含めて比較する。通信制限や既存機能を弱めない |
| 4 | 予算通知を実際の稼働構成と整合させる | 通知額の変更は節約にならない。費用上限、許容する待ち時間、必要な可用性を判断記録に残す |

11月3日の日額を単純に30倍すると386.54ドルになるが、月初の一時費用や今後の税・負荷を織り込まない計算なので、AWSの予測409.74ドルとは区別する。今の2台とDBの床、NATだけでも30日268.50ドル相当となり、100ドルの予算額とは整合していない。

実資源の停止、型の変更、IAM付与、`terraform apply`は行っていない。まず現行stateからplanを作り、変更内容、影響、検証方法、復旧方法を具体化する。

## モデル原価とプランの判断

AWSは固定費と共有負荷、外部モデルAPIはリクエストごとの変動費として分ける。AWS総額をそのまま「1問あたりのモデル原価」と呼ばない。採算計算には、成功・失敗・再試行を含む使用量と費用、完了回答数、実利用者数、決済手数料が必要である。Plus・Proの価格変更や新プラン追加は、この調査だけでは決めない。

## 再現方法と公開しない資料

取得したCost Explorer応答を再利用して、`Decimal`で日別・サービス別・使用種別別に加算した。集計式は`sum(group.Metrics.UnblendedCost.Amount)`。使用量は同じusage typeの中でだけ比較し、時間・ACU時・GBを横断して合計していない。

実行した読み取りは次の通り。アカウントフィルタは公開版ではプレースホルダーに置き換えた。

```text
ce get-cost-and-usage
  TimePeriod: Start=2026-10-27, End=2026-11-05
  Granularity: DAILY
  Metrics: UnblendedCost, UsageQuantity
  GroupBy: SERVICE, USAGE_TYPE
  Filter: LINKED_ACCOUNT=<PALS利用アカウント>
budgets describe-budget / describe-notifications-for-budget
ec2 describe-instances / describe-vpc-endpoints
rds describe-db-clusters
cloudwatch get-metric-statistics
  Namespace=AWS/RDS, Metric=ServerlessDatabaseCapacity, Period=86400
  Statistics=Average,Minimum,Maximum
cloudtrail lookup-events: EventName=DeleteDBInstance
logs describe-log-groups / describe-log-streams
```

AWS CLIの管理用プロファイルは支払元の照会にのみ使用し、本番資源はPALS利用アカウント用プロファイルで確認した。正確なアカウントID、資源ID、コマンドの生出力、メールの配信先と本文はローカルの保護対象で、Gitへ追加しない。
