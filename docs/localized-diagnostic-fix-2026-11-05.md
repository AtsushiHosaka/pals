# 多言語のworker診断とAPI契約の修正確認 — 2026年11月5日

関連[#270](https://github.com/AtsushiHosaka/pals/issues/270)、[API PR #72](https://github.com/AtsushiHosaka/pals-api/pull/72)。workerが生成する固定診断文をAPIが拒否する契約不整合を修正しました。PRは未マージで、本番配備や元のジョブの復旧はしていません。公開後の再レビューも予定しています。

## 変更範囲と固定ソース

既存の12診断コードについて、英語・日本語・簡体字中国語・繁体字中国語の固定文だけをallowlistに追加します。2つのartifact保存コードでは、旧APIの英語文との互換も保持します。任意のプロバイダー本文、未知の追記、空白の変更、別コード群の文は引き続き拒否します。

変更はソース・テスト・記録文書・オフライン確認スクリプトの4ファイルです。診断の構造、状態の整合性、workerの検証権限、Lean成功、公開共有の検証条件は変更していません。

## 実際のproducerからAPIの入力型までのオフライン照合

実際の診断生成関数、serializer、APIの入力型を通して確認しました。試行データ、タイムアウト時間、claim、非公開プロバイダー文の入力例は合成したものです。本番の要求本文を再生した実験ではありません。HTTP・DB・プロバイダー・AWS・Leanへの呼び出しはすべて0件です。

| 固定ケース | base API | 修正後API |
|---|---:|---:|
| 既知の固定診断を受理：12コード×4言語×2状態 | 20 / 96 | 96 / 96 |
| 各更新の4診断位置に未知の追記を加えた入力を拒否 | 384 / 384 | 384 / 384 |

2状態は修復中と修復回数上限による失敗です。各更新にはトップレベルと3つの入れ子の診断リストを含め、入力型の検査後も文が変わらないことを確認しました。baseの英語は24件中20件を受理し、artifactの4件を拒否しました。他の3言語は各24件をすべて拒否しました。修正後は各言語24件をすべて受理しています。

台帳ではbaseの既知文20/96、修正後の既知文96/96、修正後の未知追記拒否384/384を別の3行にします。baseでも同じ384件を拒否したことは備考に残し、分母を768へ増やしません。これは入力契約の固定ケースで、モデルの数学的な精度を測った結果ではありません。

## テストと限界

新規212ケースはbaseで80失敗・132通過、修正後は212通過でした。新規分と既存分を合わせた290件が通過し、Ruff、対象スキーマ2モジュールのmypy、差分検査も通過しました。これらの件数や構造上の負例16件は、上記の96件・384件の分母に足していません。

本番で422になった要求本文は取得していません。そのため、この修正が当該障害の原因を特定したとは断定しません。本番配備、元のジョブの修復、実環境での復旧確認は未実施です。

統合には修正コミットをAPI mainまたはリリース候補へ取り込む必要があります。今回の12コードに対応するAgent変更は不要です。既存の署名済みリリース束は書き換えません。PRやローカル検査の通過だけで、Issueを本番復旧済みとして扱いません。
