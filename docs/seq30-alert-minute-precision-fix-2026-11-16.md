# seq30の通知抑制期限の修正（2026-11-16）

[infra PR #182](https://github.com/AtsushiHosaka/pals-infra/pull/182)で、ExpireDateの秒精度をAWSが拒否した[失敗](seq30-alert-minute-precision-failure-2026-11-16.md)を修正する。変更前はinfra `ce084f345b3ebaa3fe15aee0a1519e6b0dceffaf`、修正headは`e803b4f0364d5795c913b9ba06157a75e87e94a5`。統合先は`claude/seq30-worker-trust`である。

新規作成と終了時の短縮で、元の上限を計算した後に失効日時をUTCの分へ切り捨てる。max_seconds、凍結not_after、元の失効日時を延長しない。切り捨てで有効な期間がなくなった場合はPut前に拒否する。予行の代用品も秒精度を拒否するようにし、以前の予行が実サービスの制約を見逃した境界を残す。

既知のサービス拒否は、botocoreが付ける限定した再試行情報の接尾辞があっても分類する。prefix、接尾辞の形式、既存の拒否コード一覧を限定したまま、未知のエラーや前置きwarningは未確定として扱う。今回の実stderrは保存されていないため、この接尾辞を実行時の原因とは判断していない。controllerのjournalには、alerts CLIの固定reasonだけを引き継ぎ、生のprovider出力は転記しない。成功条件やcleanupの判定は変えない。

## 決定的な検証

変更前の実装では既存alertテスト49件が通った。新しい分精度と診断の回帰を先に実行し、旧実装で失敗することを確認した。その後の修正版はalert 58件、controller 146件、予行packaging 1件が成功した。controller全体の実行時間は334.750秒で、全検査の合計時間ではない。新しいcontroller診断4テストも旧版で失敗し、修正版で成功した。

実際の失敗要求と同じ07:25:38開始・1500秒上限では、ExpireDateが07:50:00になることを確認した。終了時の短縮、再実行、期限切れ、拒否時の保存state、作成前停止、owner解放、未知または危険な診断の非採用も検査した。独立レビューとdiff検査で指摘はなかった。

これはローカルの決定的な境界検査であり、数学の精度や本番の稼働率ではない。品質台帳には検査一式を技術試行1件として追加する。実AWSで修正版を適用した検証、必須CI、統合後の全7シナリオ予行、本番受け入れは別の条件として残す。検査でAWS・モデル・本番アプリ・DBを変更していない。
