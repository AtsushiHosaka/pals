# 承認後の説明再発確認（2026-09-29）

## 判定

同じ二項平方の問題から新規説明を5件生成し、すべての本文を確認した。
指摘された「証明を終えてから同じ導出を最初からやり直す」重複は5件とも再発していない。
ただしproduction QAは4件承認・1件拒否であり、その1件は正しい分配法則を誤って拒否している。
したがって、重複の改善を確認できたが、QA全体を問題なしとは判定しない。
今回の有限個の試行から、将来の出力で絶対に再発しないとは結論しない。

## 実施方法

ユーザーが問題文・Lean証明・生成説明の既存OpenAI APIへの送信と5回の新規生成・QAを明示承認した後に実行した。
問題文に「重複しないように」などの追加指示を付けていない。

> 任意の実数 x, y に対して (x + y)² = x² + 2xy + y² であることを証明してください。分配法則を用いて説明してください。

| 試行 | 経路 | production QA | 本文精読 |
| --- | --- | --- | --- |
| batch 1 | 検証済みLean→新規説明→独立QA | 拒否 | 重複・循環・数学的誤りなし。QA理由が誤り |
| batch 2 | 同上 | 承認 | 重複・循環・数学的誤りなし |
| batch 3 | 同上 | 承認 | 導出重複なし。最後の等式の短い再掲のみ |
| batch 4 | 同上 | 承認 | 重複・循環・数学的誤りなし |
| app 1 | 実画面→新規Lean→Lean検証→説明→独立QA→保存→表示 | 承認 | 重複・循環・数学的誤りなし |

batchはproductionの生成・QAクラスを直接実行したもので、アプリ全経路を4回検証したものではない。
各候補につき生成1回・QA1回。失敗の差し替えや、同じ候補を合格するまで再審査する操作はしていない。
ローカルの修正済み実装での結果であり、未変更のmainや本番デプロイの結果ではない。
同じChrome・同じPALSタブ・同じローカルスタックを再利用した。

## 残るQA誤判定

batch 1ではQAが「分配法則の適用順として不正確」と拒否した。しかし
`(x+y)(x+y)=x(x+y)+y(x+y)` は `(a+b)c=ac+bc` の正しい適用である。
各積の展開、`xy=yx` による整理も正しい。独立した本文レビューも同じ結論だった。
元のQA判定は変更しておらず、不合格例も証跡に残した。
これは説明が出ない原因になり得る残課題であり、今回の再実行だけで解決済みとはしていない。
