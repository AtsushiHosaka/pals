# seq30予行のpreflight停止記録（2026年11月14日）

## 結果と適用範囲

infraのマージ後コミット`7ef4034c7b3fa5f3c69a8899c5c74fb68b61482c`で、7筋書きのうち最初の`success`が終了コード1で失敗した。ケースの所要時間は221.158秒、実行全体は221.281秒だった。残り6筋書きは実行していない。seq30リリースは停止中で、親の参照更新、再署名、新たな本番配備へ進めていない。

同じコミットで、原因調査のために`REHEARSAL_KEEP=1`による隔離予行を1回実行し、終了コード1で再現した。実行部分は160.476秒、証拠回収を含む全体は162.268秒だった。この調査は7筋書きの受け入れゲートに数えない。

## 保存した事実と未確定事項

再現時の外側の結果は`control_read_only_preflight_refused`、operatorの終了コードは2だった。内側の結果は次のとおり。

```json
{"status":"native_update_refused","phase":"owning-module-bytes","error_class":"ValueError"}
```

この段階では、Dockerによるモジュール読み取りコマンドの失敗と、読み取ったハッシュの不一致が、どちらも同じ`ValueError`として記録される。保存した結果だけでは両者を区別できない。実際にハッシュが不一致だったとは確認しておらず、停止原因は未確定である。

期待するハッシュは予行のproductソースから作られ、productイメージも同じソースをコピーして作られる。該当する生成経路とpreflightコードはe339から7efまで変更されていない。この一致は、実行時のDocker読み取りが成功した証拠にはならない。

再現時には`serving_actors_unchanged=true`、タスクのcleanupはすべてtrueだった。データベースへのapply、IAM変更、drain、activationは実行されていない。タスク専用のコンテナ、イメージ、ネットワーク、ボリュームも回収された。実AWS、有料モデル、本番に対する変更は行っていない。隔離予行の代用品による結果であり、本番や数学回答の受け入れを示さない。

## 診断変更による原因の確認

診断変更を固定した`8b19b2294beed1edc7a6866744c77073a1ad10ec`で、開発用の隔離実行を1回行った。終了コード1、実行時間161.938秒で、証拠の初回回収まで162.058秒だった。後続の調査と回収処理を含む総時間は測っていない。内部結果は`owning-module-read-command`の`ValueError`となり、ハッシュ比較の前に失敗した。

保存した環境で同じDocker引数を実行すると、終了コード1、stdoutは0バイト、stderrは`PermissionError`だった。イメージ内のappディレクトリはroot所有の0700、ファイルは0600で、検査用ユーザー65532では探索できなかった。rootで読み取ったモジュールのSHA-256は`da4535268af04c3135f58c9d758b8f6c9cffc94135224a23b4f04837fdb669a3`で、元ソースと期待する照合値に一致した。

原因は実行ラッパーとコピー処理の組み合わせだった。ログの権限を制限するためラッパーで設定した`umask 077`が予行へ引き継がれ、macOSの`cp -R`でソースの0755・0644が0700・0600へ変わった。同じコピーをumask 022で行うと0755・0644となり、どちらもバイト列は同じだった。本番のソース不一致やoperatorの実行権限を原因とは扱わない。

診断後は専用コンテナ5個、ネットワーク1個、ボリューム4個、イメージタグ10個を削除した。実AWS・有料モデル・本番への変更はなく、この実行も受け入れゲートには数えない。修正対象は予行用ビルド領域の権限で、本番の検査ユーザー、ハッシュ照合、安全条件は維持する。
