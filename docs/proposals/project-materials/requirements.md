# プロジェクト資料添付 — 仕様案

状態: WORKING。2026-09-30の回答で確定した機能と、数値未確定の料金条件を分ける。既存の正本・実装・請求設定をこの文書だけで変更しない。実装済みの範囲の正本は [specs/project-materials](../../../specs/project-materials/requirements.md)。
目的: Project資料の閲覧・ページ出典と、チャットへの画像入力を実現する。inline画像の実装もユーザーから依頼済み。

## 決定済みの範囲

- プロジェクト資料はPDF・PNG・JPEGのみ。各プロジェクト最大5ファイル、各50MB（50,000,000 bytes）。
- プロジェクトホームから資料を開く。回答中のページリンクを押すと右サイドパネルに対応する原ページ画像を表示する。単独画像はその画像を表示する。
- PDFはスキャンを含めて最初から全ページを処理対象とする。利用者に処理ページの選択を要求しない。軽量約1,000ページPDFを受入試験に含める。
- 削除した資料の過去リンクは参照切れとして表示する。過去の回答本文は書換えず、削除済み原本・ページ画像をそのリンクから閲覧できない。
- 有料プラン加入中のみプロジェクトの新規作成・資料追加を許可する。解約後も既存プロジェクトと資料は閲覧できる。既存資料を使う新規質問には通常の利用枠が必要。
- プロジェクトなしのチャットでも画像を直接添付できるようにし、画像の枚数・読取り量に応じて利用枠を多く使う。
- 証明生成・独立QA・説明まで成功して提供できた時点で消費を確定し、失敗では消費しない。説明再試行でも二重消費しない。内部原価は成功失敗を問わず別に記録する。
- 長い証明ほど消費が増えるトークン制にする。アカウントメニューと設定の「使用量とプラン」に残量、予約量、更新日を表示する。

## トークンと料金の決定

D11: 生tokenの単純合算ではなく、入出力・画像等の処理負荷を換算した「利用トークン」を使い、換算規則を利用者へ表示する。
D12: 成功した依頼の生成・内部修復・独立QA・説明を含む全工程を集計し、送信前に表示した消費上限を超えない。失敗時の消費は0。

D1–D12の回答済み事項は再確認しない。金額、プラン別の総保存量・全ページ解析枠・token枠、失敗を含む試行制限は[料金案](pricing.md)と実測で詰める。inlineはPNG/JPEG最大5枚・各50MBの案を維持する。外部処理物・バックアップの削除期限は実装前に固定する。

## 要件案

| ID | 要件と受入条件 | 決定への依存 |
|---|---|---|
| MAT-001 | 本人所有の各プロジェクトに最大5件。uploading/processing/ready/failedを合算する。同時送信でも6件目を受理しない。失効・削除の件数と容量の解放時点は設計の状態表に従う。 | 確定 |
| MAT-002 | 各ファイルは50,000,000 bytes以下。空・上限超過・非対応形式・実形式の不一致を理由付きで拒否する。クライアント申告だけで判定しない。 | 50MBを十進byteで定義 |
| MAT-003 | プロジェクトホームの資料一覧に名前・容量・処理状態・エラーを表示し、クリックで資料を開ける。追加/取消/再試行/削除/閲覧を行える。閲覧時も埋込コード・自動外部通信を実行せず、資料からアプリの認証情報へアクセスできない。4言語UI・キーボード操作・進捗通知を既存仕様に合わせる。 | 確定 |
| MAT-004 | PDF全ページを処理し、文字層・スキャン・混在を判定して必要な画像読取りを行う。全ページの完了前に全体を利用可能にしない。読めないページを飛ばして成功にしない。ページ別進捗と失敗を示す。暗号化/破損/資源超過は有限時間で終了し、修正方法を示す。 | 全ページ処理は確定。資源・期間予算の数値は未決定 |
| MAT-005 | 本人・対象プロジェクト内の利用可能な資料だけを検索し、1質問への入力量を制限する。新資料・改版は実行済みの証明/回答を変更しない。 | ページ出典機能として設計 |
| MAT-006 | 採用した出典は原本版・抜粋・ファイル名・PDFの実ページ番号または単独画像へ結合する。ページリンクのクリックで右サイドパネルに対応する原ページ画像を表示する。存在しない出典を表示しない。資料は未信頼の参考情報であり、命令や検証済み証明として扱わない。 | ページ出典機能として設計 |
| MAT-007 | 証明の仮定・目標・Lean検証・独立QAの条件は維持する。資料によって仮定を黙って追加しない。資料から問題文を補完する場合、元の依頼・確定する命題全文・資料版/範囲・利用者の確認を結合して保存する。未確認の抽出命題では生成を開始しない。独立QAは原本の対象範囲との対応と、その確定命題に対するLean命題を別々に確認する。 | 命題補完時の確認UIは設計案 |
| MAT-008 | 削除要求後は新規の参照・原本アクセス許可を止め、処理中の結果も再公開しない。既発行URLの最大残存時間を明示する。原本・抽出文・検索索引・外部処理物を対象とした削除を追跡する。過去の回答は残し、その引用リンクは「資料が削除されました」と表示する。削除後はページプレビューを再生成・表示しない。 | 参照切れ表示は確定。削除期限と進行中jobは設計対象 |
| MAT-009 | 取込・生成の各処理の開始時に、それぞれ必要な利用枠をサーバー側で原子的に予約し、重複通知・再送・失敗・取消で二重消費しない。取込開始ではproof枠を予約しない。容量枠の解放と有料処理枠の返却は別の規則にする。 | 単位・対象工程は確定、換算係数と付与量は料金案 |
| MAT-010 | 外部AIへ送る内容・送信目的・保持範囲を取込前に説明する。私有資料を共有Draft/Recipeへ自動登録しない。本文・画像・署名URLを運用ログへ記録しない。 | provider選定と保持条件 |
| MAT-011 | Projectに属さないチャットとProject内チャットの双方で、本文とPNG/JPEG画像を同じ送信に添付できる。画像はProject資料へ自動追加しない。送信前にpreview/除去、送信後に履歴から閲覧できる。画像を実モデル入力に結合し、画像の問題・数式・図を踏まえて処理する。 | 実装依頼済み、換算方式確定 |
| MAT-012 | 新規Project作成・資料追加をAPI側の有料資格で判定する。未加入時は条件を説明し、作成/送信を行わない。既存データを無断削除しない。 | 有料資格と解約後閲覧は確定 |
| MAT-013 | 独立QA済み説明を表示可能な状態で保存するまで利用tokenを確定消費しない。重複終端・再試行・期間更新でも返却や消費は一度だけ。説明失敗でLeanのverified状態を変更しない。 | 成功条件と失敗無消費は確定 |
| MAT-014 | 短い依頼と長い依頼を固定1回として数えず、処理量に応じたtokenを消費する。送信前の見積上限と実際の確定消費を区別し、失敗時は予約を解放する。画像・資料参照を含む同じ依頼の再送を二重計上しない。 | 方式・全工程・上限は確定、プラン付与量は料金案 |
| MAT-015 | 設定は「一般」と「使用量とプラン」を分ける。一般で既存の表示言語・出力言語・記号設定を操作でき、使用量で現在プラン・残token数/割合・予約中・更新日時を表示する。アカウントメニューから使用量/設定/ログアウトに移動できる。取得失敗を残量0や無制限と表示しない。 | 機能は確定、token schemaは料金設計 |

## 非対象

共同編集、公開共有、外部URL取込、ZIP、動画・音声、TXT/Markdown/DOCX、inline PDF、添付だけによる証明の自動開始、資料の定理を無検証でLeanの公理にすること。プロジェクトをまたぐファイル/チャット移動は今回追加しない。

## 完了判定

処理量・料金・削除期限を決定し、設計・タスク・既存CORE/BILLとの差分を整合させた時点で仕様レビューを行う。仕様レビュー合格は実装完了ではない。実装時は50MB境界、5件同時競合、1,000ページの実資料、数式・日本語・スキャン混在、所有者分離、削除競合、出典とLean/QAの結合を実環境で確認する。
