# 数学設定の本番リリースと認証切れの回復を準備した

2026年10月7日の公開版調査では、数学設定APIの応答からプロキシでの遮断が疑われた。
本番のDBリリース一覧にも数学設定が含まれていなかったため、署名付き更新と限定ルートを追加した。
また、認証更新が拒否されても画面がログイン状態を保持する不具合を修正した。
修正は検証済みのDraft PRとして保存した。本番への適用とログイン後の確認は未完了である。

## 数学設定は公開ルートとDBリリースの両方が不足していた

14:16〜14:21 JSTの公開API調査結果は次のとおり。認証トークンは使用していない。

| リクエスト | 結果 | 判断 |
| --- | --- | --- |
| GET `/health` | 200、APIのJSON、Caddy経由 | APIは応答している |
| GET `/v1/auth/me/math-conventions` | 404、`Not found`、APIのCORS・request IDなし | API到達前の遮断と推定 |
| GET `/v1/billing/summary`・`/v1/billing/plans`・`/v1/chat-search` | 401、APIの`auth_required`、正しいCORS | 未認証時のAPI応答は正常 |
| OPTIONS `/v1/billing/summary`・`/v1/chat-search` | 200、公開フロントのOriginを許可 | この範囲のCORSは正常 |

数学設定の旧実装は本番リリース一覧に未登録だった。既存25段階から26段階への変更だけを許すMac v4更新を追加した。
旧データと権限を保持し、追加表の所有者・権限・構造を確認する。失敗時はDDLとリリース承認を同時に取り消す。
通常のAPI起動ではDB構造を変更しない。

公開プロキシには、数学設定のGET・PUT・OPTIONSだけを通すCaddy設定を用意した。
本番ホストの既存Caddyfileは取得できていないため、実際の上流アドレスを使った組み込みは未実施である。

## 認証更新の拒否後にログイン状態を解除する

期限切れのアクセストークンを更新し、Cognitoが`NotAuthorizedException`を返す場合の不具合を再現した。
画面がログイン状態を保持していたため、有効なトークンがないまま設定や検索の再試行が続く。
修正後は、この拒否を受けた時点でログイン状態を解除する。通信障害では入力を保持し、再試行できる。
新しいログインの後に古い更新処理が失敗した場合も、新しい認証情報を保持する。

この不具合は検索・プラン設定の失敗と整合するが、元の報告の原因だとは断定できない。
QA報告には失敗時のHTTP応答が残っておらず、調査に使った既存タブはログアウト状態だった。
ログイン後の公開版確認をユーザーに依頼している。

| 対象 | 検証結果 |
| --- | --- |
| フロントの関連テスト | 18ファイル・164件成功。型チェックと変更箇所のESLintも成功 |
| APIの最終対象範囲 | 87件成功・12件skip。ruff成功。mypyの新規エラーなし、既存12件は残る |
| 署名付きMac v4更新 | 実PostgreSQL 16で6件成功。全行・ACL保持、再適用、改変拒否、DDLと承認のrollbackを確認 |
| 数学設定の初回導入処理 | 実release principalで導入・再実行・ACL復元・rollback・構造と権限のずれの拒否を確認 |
| ホスト更新プログラム | 56件成功。実API validatorとEC署名を使ったオフライン連携も成功 |
| 公開プロキシ設定 | Caddy 2.10.2で完全な候補設定のadapt・validateが成功 |
| 検索API | 関連33件成功。実PGの自然文proof request検証10件と、新旧データ共存・所有者分離・カーソル等の追加検証1件も成功 |

独立レビューで指摘はなかった。検索SQLの不具合は確認できていない。
古い検索integration fixtureは必要な表がなく、検索処理に入る前に失敗したため、検索APIの障害根拠には使っていない。

本番ホストとAWS KMSは未検証である。完全な新規署名付きbootstrapも未検証のまま残る。
その確認に必要だったfixture DBの再初期化は、所有確認不足と不可逆な削除を理由に自動承認レビューで拒否されたため停止した。
検証終了後、作成時のID・所有ラベル・tmpfs・永続マウントなしを確認し、このチャット専用コンテナの削除は承認されて完了した。

## 本番適用と認証付きの確認が残る

修正PRは[フロント #6](https://github.com/AtsushiHosaka/pals-webfront/pull/6)、[API #4](https://github.com/AtsushiHosaka/pals-api/pull/4)、[infra #2](https://github.com/AtsushiHosaka/pals-infra/pull/2)。
親リポジトリの参照は、それぞれのpush後に更新した。

本番では、ホスト管理の手順で更新プログラムを置き換え、固定された実行ファイルhashとv4 capabilityを更新する必要がある。
署名付きDB更新後、既存Caddyfileを保持して限定ルートを組み込み、フロントを反映する。
適用後に数学設定の読込・保存・再読込、プラン設定、チャット検索と再試行をログイン状態で確認する。
PRの作成だけでは公開版の復旧を示せない。
