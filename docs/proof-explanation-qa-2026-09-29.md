# 証明説明の重複とQAの調査（2026-09-29）

対象はローカルの証明 `6c8d2059-b4f4-44c1-813d-2af3af546cec`。
実数の二項平方を分配法則で説明する要求に対し、冒頭で証明を完結させ、本文で同じ導出を再開していた。
この重複自体は論理的矛盾・循環論法ではないが、一続きの証明という出力要件を満たさない。

## 確認した原因

- `proof_output_reviews` に当該本文への独立QA承認が実在する。2026-09-29 02:00:08 UTC、モデルは `gpt-5.4-mini-2026-03-17`。生成とレビューのセッションは別。
- 承認理由は分配法則・可換性による導出がLeanの定理に一致し、日本語として問題がないというもの。説明全体の重複は審査基準に含まれていなかった。
- 生成指示には連続した証明を書く指定があったが、生成が違反してもQAは数学的正しさだけで通していた。
- 有効な不合格判定の後も、同じ候補を変更せず再審査していた。後続の合格判定で公開できる経路を回帰テストで再現した。
- APIは本文・Leanのハッシュ、独立セッション、承認、claim期限、参照の一致を確認する。これは承認対象の同一性を保証するが、モデルの判断の正しさを保証するものではない。

## 変更

- 生成時の `overview` は変数・対象・仮定の短い導入とする。導出は `sections`、最後の結論は `conclusion` とし、冒頭での方法予告・証明の完結を避ける。
- 独立QAに実際の表示順の文章を渡し、JSONキー・非表示タイトル・参照コードと区別する。
- 同じ導出の繰り返し、証明の再開始、結論の先取り、循環論法、根拠のない言い換えを拒否する。短い最終結論、推論に必要な式の再使用、適用条件を満たす標準定理、正しい背理法は許容する。
- 有効な `approved: false` はその候補について確定し、承認を得るための再投票を行わない。不正なJSON/schemaの再試行は維持する。
- UIの「検証済み」を「形式証明をLeanで検証済み」に変更。説明文そのものをLeanが検証したとの誤解を避ける。本文を隠して重複を取り繕う変更はしていない。

- 説明関連90テスト、workerのclaim・公開関連70テストを確認。明確な却下の後に合格応答が来ても消費せず停止する回帰を含む。

## 制約

既存のcompleted説明を再生成する公開APIはなく、保存済み本文・不変の承認記録は変更していない。今回の生成・QA修正は新規生成に適用される。
既存説明を更新するには、追加質問が参照する旧説明と承認履歴を保持するリビジョン設計が必要。

LLMによるQAは自然言語の完全な形式検証ではない。今回の実測は限定した回帰例の確認であり、全説明の正しさを保証しない。
一部の拒否理由には数学的に不正確な指摘も混じったため、判定理由も含めた継続評価が必要。
