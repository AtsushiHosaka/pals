# 失敗回答の分析とv4の比較

前回の24試行、修正前も含む26回答、採点が下がった14組を点検しました。説明上の欠陥に加え、レビューの不適切な拒否と、表示処理による結論の欠落が見つかりました。点数の低下だけを数学的誤答とは扱いません。進行は[Issue #317](https://github.com/AtsushiHosaka/pals/issues/317)に記録します。

## 実際の回答で見つかった問題

| 対象 | 実際の表現・挙動 | 分析と扱い |
| --- | --- | --- |
| 二乗関数の連続性 | 「差の平方は」と書き、続けて`(x−a)(x+a)=x²−a²`を示す回答がある。 | 式は正しいが、名称は「平方の差」。基準条件でも候補でも起きており、候補だけの欠陥とはいえない。 |
| 二乗関数の連続性・v2の2回目 | 定数の正値性、δの選択、近傍の条件、因数の評価、最終評価を一段落に詰め込んでいる。 | v2の「一段落に一つの推論」という指示に従えていない。数学的には妥当でも、説明の依存関係を追いにくい。 |
| √2の無理性・v3の1回目 | 分子を自然数として選んだ後で、非負に取れる理由を説明している。 | 仮定・対象の選択と、その正当化の順番が逆転している。定理の誤りは確定していない。 |
| √2の無理性・v2の1回目の修正回答 | レビューが、積の平方の式`(xy)²=x²y²`の呼称を不適切だとして拒否した。 | 実数について式も呼称も妥当。「定義からの展開」と「積のべき乗の法則」のどちらかしか認めない理由はない。拒否理由に根拠がなく、説明を返せなかった原因として記録する。 |

| 結論の表示 | 構造化回答のconclusionにある「したがって無理数である」などが、本文への変換で落ちる。 | 書き手・レビュー器はconclusionが表示される前提なのに、APIは使っていない。プロンプトだけで解決する問題と分け、比較では表示処理を同一に保つ。 |

連続性の証明で不等式の間を一文でつなぐ説明や、既約分数を選んだ理由を使う位置で思い出させる説明は、学習者には有益な場合があります。これを一律に重複として削ると、推論が飛ぶおそれがあります。また、簡潔さの0.01の差や数学的正しさの0.99という採点だけから、誤答を認定することはできません。

前回のv2/v3は、既存プロンプトにもある重複抑制を繰り返す性格が強く、説明の組み立て方が具体的ではありませんでした。今回のv4は、定義と仮定を先に置き、局所的な事実・その理由・新しく得た事実の順で短い段落を作る方針です。曖昧な法則名を付けるより、正確な式と役割を述べるようにしています。参考解答や問題別の正解は生成器に渡しません。

## 比較条件

前回3題は元のマニフェストと固定したcollectorを使い、基準条件も生成し直します。追加3題は、実行前にソースと処理系を照合し、秘密を渡さない別プロセスで再コンパイルしたうえで、同じ説明生成・レビュー・表示・独立採点の経路を使います。各条件は各問題2回です。比較対象は合計6題、新しい説明の試行は合計24件です。

追加3題では、ソースの証拠を読み込む処理と問題集が異なるため、前回3題との点数を直接つなぎません。同じ問題・モデル・採点基準・試行数の変更前後を比較し、グラフも既存問題と追加問題に分けます。前回の悪化や失敗はそのまま残します。主指標はわかりやすさで、数学的正しさ、論理の完全性、記号の一貫性、説明を返せた件数も確認します。

新しい問題は、幅広い利用者や分野を代表する無作為な検証集合ではありません。採点はLLMによる代理指標です。小さな差が出ても、そのまま学習者の理解や一般的な精度向上と解釈しません。
