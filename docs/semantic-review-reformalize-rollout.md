# 意味の審査の作り直し: 有効化の手順と危険（`PALS_SEMANTIC_REVIEW_REFORMALIZE_ENABLED`）

1. 前提: pals-api#108 を含む API を署名リリースで配備する（フラグは既定 off のまま。worker の変更はない）。有効化は、API のランタイム環境に `=true` を足す別の署名リリース。
2. 動作: 最初の Lean ジョブが意味の審査で不合格になった dsp 依頼に、新しいジョブを 1 つ作る。ゲスト・後続ジョブ・最初のジョブの実行が 600 秒超（未検証の期限が有効なら期限 − 150 秒超）の依頼は対象外。2 回目の不合格は従来どおり失敗。
3. 費用: 却下された依頼だけ、1 回分の生成費用が増える（約 US$0.04〜0.07/件。要件指定の題では全体で +27%）。却下されない依頼は変わらない。却下率の本番値は未確認（回帰セット: 要件指定の題 3/12、一般の題 1/12）。
4. 時間: 却下された依頼の回答が約 +100〜160 秒。本番の p90 877 s の依頼は 600 秒ガードで対象外になりうる。
5. 画面: 作り直しの間は `verifying` のまま。経過時間の表示だけ、新ジョブで 0 に戻る（文言は不変）。
6. 監視: `failure_reason=semantic_review_failed` の件数、`proof_request_lean_jobs` が 2 件の依頼数（作り直し率）、作り直し後の `answered` 率、依頼の所要時間 p50/p90、依頼あたりの生成費用。
7. 判断の目安: 有効化後 1 日、作り直し後の `answered` 率が低い、または費用の増分が想定（却下件数 × 約 US$0.05）を超えるなら戻す。
8. 戻し方: 環境変数を外す（または `false`）署名リリース。進行中の作り直しジョブは通常のジョブとして完了し、新たな作り直しは起きない。DB 移行はなく、データの巻き戻しは不要。
9. 注意: 旧版 API へ戻す場合は、保存済みの `lean_semantic_review_*` が公開の `error_code` に出る（pals-api#106）。画面が未知のコードをどう表示するかを、戻す前に確かめる。
10. 根拠: [測定と設計](improvement-journal/entries/2026-11-14-semantic-review-reformalize-job.md)、pals-api#108、pals-agent#137。
