# Fast proof request design

A new proof-request aggregate is separate from the existing formally verified proof job. The ordinary Send action in both composers creates this resource; there is no learner-facing Lean mode selector or additional consent step. Its durable state is queued → assessing → needs_input/answered/failed. Answering a question advances the revision and requeues the same request. The existing SQS worker recognizes proof_request:<UUID>; the API owns persistence, ownership, quota, dispatch recovery, leases and settlement. The agent owns all prompts, catalog retrieval and mathematical decisions. No model client belongs in the API.

Public API: POST/GET /v1/chats/{chat_id}/proof-requests, GET /v1/proof-requests/{id}, POST /v1/proof-requests/{id}/answers and /retry. Create supplies statement/idempotency_key; answer supplies question_id/expected_revision/answer/idempotency_key. Response contains id/chat_id/status/revision/statement/output_language/question/answer/context_turns/created_at/updated_at/error_code. Answer evidence_kind is llm_assessed; sources contain draft_id/revision/statement. Internal authenticated claim, usage and settlement operations are fenced to the current lease and revision.

The agent performs a bounded premise assessment, obtains candidates through real existing catalog ports, and makes a structured reuse/instantiation decision. Store actual model identity and application evidence. Use Luna for the default and Terra only on unresolved mathematical decisions. Invalid premise/answer schemas, unavailable providers/catalogs and exhausted retries yield explicit failure. A locally rejected model-generated retrieval query is a narrower case: record query_invalid, keep its usage, and let the already-budgeted final assessor derive an independent proof with no sources or substitutions. Enforce those restrictions in code. Do not claim a requested source was retrieved; if the user explicitly requires that source and it cannot be obtained, return unsupported. Provider, catalog transport, metadata and source-integrity errors never use this fallback. The new path never calls Lean and never manufactures a compiler receipt. The candidate assessment and the independent review of the exact rendered answer are the answer-acceptance gates; Lean execution or success is not a gate. A stored theorem may be specialized only with typed, scope-preserving substitution and discharged premises. Distinguish proof dependency edges from related-Draft references when checking cycles.

The assessor schema exposes instantiation only for structurally discovered leading universal numeric parameters. Concrete lambda inputs are never substitution parameters; the actual selected-source validator remains authoritative. Derived hints do not change source revision hashes. The single independent answer review uses a 12000-output-token ceiling and a bounded 1–2000-character rationale schema; ordinary generation calls retain 6000. All output, including reasoning, enters the exact permit/receipt accounting. Its existing 45-second call limit remains clipped by the 180-second runtime deadline and 240-second claim lease. Incomplete verdicts and insufficient original operation budgets remain failures; no automatic paid retry or quota increase is added.

Quota holds share the legacy account entitlement lock/count. Release on needs_input or failure, reacquire on continuation, consume at answered. Keep token cost telemetry regardless of status. Bounds: at most five premise rounds, two learner retries and three delivery attempts per revision; admission also has an account rate limit. Public results omit prompts and provider internals. Context belongs to the exact owner/chat/request and is not shared with another learner.

Frontend retains legacy proof display and replaces new submissions with proof-request creation/continuation. It polls only active work, uses abort and owner/chat scoping, retains idempotency keys after ambiguous sends, and refuses mismatched response identities. Question options are optional; free text always works. A question answer is never submitted as an unrelated new theorem. Source and evidence details are secondary to the mathematical answer.

## Existing Draft catalog integration (runtime finding, 2026-09-30)

The existing local catalog contains real `public.dsp_drafts` rows, including universal power continuity, but has no active new PFI/typed publication. Natural-proof retrieval therefore has a distinct worker-authenticated read-only candidate port over these existing sketches. The API owns its dedicated reader credential, bounded top-eight vector query, embedding fingerprint checks, canonical payload validation and exact source content hash. The agent receives candidates without any publication/Lean approval claim and must reconstruct/assess their argument. Do not manufacture a publication receipt, bypass a formal catalog admission gate, or alter formal PFI/typed selection. Only actually available typed profiles may be used by the new runtime. The preserved older embedding metadata is not repurposed as a false generation certification.

The natural retrieval query is an untrusted search hint, not an admitted theorem or a source of substitution types. Generate a bounded strict JSON tree and serialize canonical v2 OpenMath for the real legacy embedding contract. Keep exact source v4 validation/content hashes and numeric-only instantiation separate. Natural retrieval evidence records actual cosine distance and source identity; it does not manufacture formal PFI equivalence scores.


## Provider text and durable JSON storage

Parsed provider JSON must contain Unicode scalar text compatible with PostgreSQL JSONB. Reject U+0000 and unpaired surrogates in every string and key before retaining an assessment, computing the answer hash or requesting independent QA. The strict provider schemas exclude NUL, while the local parser remains authoritative. Never strip or rewrite proof text after QA. Invalid provider text produces the existing `proof_reuse_invalid_response` failure with only earlier valid evidence and no automatic paid retry.

The API's existing recursive closed-command Unicode validator also rejects NUL before repository entry. This is a 422 input/contract rejection, distinct from a transient persistence 503. A failed operation must still persist safe failure evidence and release its original hold without losing already-recorded provider receipts. Exact valid answer bytes and independent QA binding remain unchanged. October 2's repeated square request exposed NUL in the private-evidence JSONB write; its finer nested field is unavailable from retained logs and must not be invented.
