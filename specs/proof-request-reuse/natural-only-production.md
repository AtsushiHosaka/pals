# Natural-only production capability (WORKING addendum)

**Superseded for ordinary Send on 2026-10-05.** Every new answer now requires Lean (PFR-010–PFR-013). A `natural-only` deployment cannot serve ordinary Send: requests that need Lean must fail explicitly there (PFR-013), and production must run with `PALS_PROOF_CAPABILITY=full` and its verifier/reconciler. The contract below remains only as the description of the existing capability switch.

The October 2 direct correction requires ordinary Send → AI assessment → answer, with no mandatory Lean and no new Lean action. This bounded operator capability implements PFR-002/005/006/007/008 and CORE-003/006/012 without changing proof verification, owner checks, independent exact-answer QA, model roles, token caps/receipts or signed database admission.

| ID | Contract |
|---|---|
| NAT-PROD-001 | API and Agent accept exactly `PALS_PROOF_CAPABILITY=full|natural-only`. Absence defaults to full. Unknown, blank or padded values reject startup. Agent validates both environment parsing and direct dataclass construction. `local_runtime` is a separate existing local-only contract and cannot enable production authority. |
| NAT-PROD-002 | Natural-only production retains real authentication, ordinary PFR repository/claim/outbox/QA/usage/token operations and the least-privilege natural draft catalog URL. `PALS_PFI_DRAFT_READER_DATABASE_URL` remains required despite its legacy name. Optional formal selector/reviewer/artifact/reconciler configuration is not required when formal execution is disabled; validation of any supplied credentials remains unchanged. |
| NAT-PROD-003 | After existing user/worker/dedicated reviewer authentication, disabled public formal creation/clarification/retry and internal formal claim/candidate/review/update/input/usage/selection/curation/typed paths refuse execution with 503 before admission, mutation, queue dispatch, usage or model work. Generic worker authentication remains shared and unchanged for ordinary PFR/token routes. The private PFI middleware receives its existing unavailable implementation even if a formal service was injected. |
| NAT-PROD-004 | Owner-scoped job history/status/source/explanations/clarifications/recovery/SSE stay readable through their existing repositories and serializers. Existing verified history retains actual verification/source status; capability selection does not manufacture or downgrade verified evidence. Other owners stay denied. |
| NAT-PROD-005 | Natural-only API startup skips formal dispatch recovery/redrive, explanation recovery/tasks and candidate runtime tasks, even when stale formal objects are supplied. Ordinary PFR outbox processing and shutdown remain active. Disabled formal composition does not eagerly instantiate Recipe selection/curation/reconciliation services. Existing authoritative startup/database gates remain in force. |
| NAT-PROD-006 | Natural-only worker CLI composes only the existing ordinary request processor. No formal explainer/reviewer/planner/pipeline/PFI initialization occurs. Valid formal SQS deliveries remain unacknowledged for a capable worker/redrive; rejection occurs before claim UUID/API/provider/visibility extension/deletion. Direct formal processing entry points return without API work. Ordinary receipt/lease/QA/accounting/ack behavior is unchanged; drain/poison behavior remains bounded. |
| NAT-PROD-007 | `Dockerfile.natural-production` uses the existing pinned Python base and installed package, nonroot UID, explicit natural-only capability and ordinary worker command; it requires no Lean/Ollama/PFI seed/provenance artifact. The full Dockerfile is unchanged. No fake fingerprints or image/toolchain admission fields are introduced. |

Operator configuration retains the existing `PALS_TOKEN_ACCOUNTING_ENABLED=true` activation flag in API/Agent alongside `PALS_ENV=prod`; capability selection does not itself activate token accounting. This existing billing configuration is explicitly approved and introduces no learner-facing action.

Passing local injected-boundary regressions is not production admission, real provider, queue, AWS KMS, Mini mount, image build, or restore evidence. The full signed production database manifest is never skipped or reinterpreted by this mode. Its current Recipe role-normalization failure requires a separately reviewed initial bootstrap authority correction; no release CREATEROLE or blanket master migration fallback is authorized by this addendum.
