# PALS Product Requirements

## Purpose

PALS の最小体験は、数学の問いを送信し、Lean による形式検証を経た証明とその自然言語の証明文を得ることです。学習者に検証経路の選択を求めません。Lean を経ずに作られた過去の回答は、その証拠に即した状態で引き続き閲覧できます。
この文書は学習者に見える振る舞いだけを定義し、実現方法は定義しません。

## Requirements

| ID | Requirement |
|---|---|
| CORE-001 | 学習者は、自然言語の数学問題または形式的な命題を証明要求として送れる。 |
| CORE-002 | Lean による形式検証済みの証明として表示する場合に限り、PALS は証明候補を生成し、その証明の Lean source が Lean のコードとして `sorry`、`admit`、`axiom`、`constant`、`opaque`、または `unsafe` を一切含まず、その実際の Lean 検証に成功し、その source 内でこの証明候補の対象として一意に識別された形式的命題が元の証明要求に対応し、証明候補の論理が妥当であることを生成担当とは別セッションの LLM がレビューして成功した場合だけ、その証明を `verified` と扱う。Lean Recipe Catalog の登録済み Recipe を再利用する場合は、その Recipe が登録時に同一 source・同一 toolchain fingerprint で Lean 検証に成功した記録を持ち、その fingerprint が現在の検証環境と一致することを、その source の実際の Lean 検証の成功とみなす（再コンパイルしない）。命題の対応と論理のレビュー条件は同じとする。 |
| CORE-003 | 正常な回答には、元の要求・確定した前提・AI が確認した論理に基づく、当該要求で選択された回答言語の数学書風の証明文を提示する。形式検証済みの履歴では、検証に用いた形式的命題と Lean source にも忠実でなければならない。証明文は節見出し、箇条書き、会話調の手順分割を用いず、`Fix`、`Let`、`Set`、`Assume`、`Therefore`（各言語の同等表現）のように直接本文を進める。形式検証済みの履歴では、Lean tactic の逐語訳は要求せず、自動化された source であっても検証済みの定理と数学的帰結に忠実でなければならない。形式検証済みの履歴では、学習者は本文の一部について追加質問でき、その証明文に基づく当該要求の回答言語の回答を受け取れる。 |
| CORE-004 | 生成、Lean 検証、または証明要求と形式的命題の対応および証明候補の論理を確認する LLM レビューが失敗した場合、成功を捏造せず、対象の証明候補を未検証または失敗として当該要求の回答言語で明示する。説明または追加回答が失敗した場合は、その出力を当該要求の回答言語で失敗として明示する。CORE-002 の全条件を満たして既に `verified` と表示された証明は、後続する説明または追加回答が失敗しても `verified` のままとする。 |
| CORE-005 | Lean source を持つ証明では、学習者はその source を確認できる。`verified` と表示された証明では、確認する source は `verified` 判定に使用した source と同一である。通常の学習画面では説明を初期表示し、Lean source は学習者が source 表示操作をしたときだけ表示する。 |
| CORE-006 | PALS は証明の回答、説明または追加回答を学習者に提示する前に、生成担当とは別セッションの LLM によって、要求・確定した前提・論理との整合性をレビューする。形式検証済みの履歴の出力では、対象の検証済み証明（追加回答では対象の説明も）との整合性もレビューする。レビューに成功した出力だけを提示し、レビューが失敗した場合はその出力を当該要求の回答言語で失敗として明示する。証明の `verified` 状態は変更しない。 |
| CORE-007 | 学習者は、英語 (`en`)、日本語 (`ja`)、簡体中文 (`zh-Hans`)、繁體中文 (`zh-Hant`) から「言語」をアカウント設定として選択できる。この1つの設定が、画面の言語と回答の既定の言語を同時に決める。学習者は、回答の言語だけを別に明示して選ぶこともできる。この選択は画面の言語と独立に保たれ、明示的に選んだときだけ画面の言語と異なる。設定は永続化し、同じアカウントを使う端末間で共有する。アカウント作成直後の初期値は CORE-016 に従う。 |
| CORE-008 | 学習者は Project 配下または Project に属さない形でチャットを開始できる。`New chat` とホームの証明要求送信は Project を作成せず、Project に属さないチャットを開始または選択して続行する。Project 作成 dialog は `Create project` または `Start a project` の明示操作時だけ表示する。PALS はチャットの開始時に、その時点のアカウントの既定の回答言語（CORE-007、CORE-015）を、判別できない入力への初期値として保存する。証明要求、説明、追加回答、失敗表示および状態表示は当該チャットに属し、CORE-015 で選択した回答言語を用いる。アカウントの言語設定または回答言語を変更しても、既存のチャットの初期値と生成済みの履歴は変更しない。 |
| CORE-009 | Chat 導入前から存在する各 proof job は、Project に属さない専用のチャットに移行する。PALS はそのチャットの言語を日本語 (`ja`) として保存する。 |
| CORE-010 | 学習者は、検証済み証明の説明および補足回答で使う数式記号の表示設定をアカウント設定として保存できる。保存済み設定は同じアカウントで利用する端末間に反映する。設定は数式の学習者向け表示だけを変え、証明要求、Lean source、検証に用いた形式的命題、生成済み本文、および証明の検証状態を変えない。 |
| CORE-011 | 保存情報から自動再開できないと確認された処理には、進行中の表示に代えて理由を当該要求の回答言語で示す。保存情報が不整合で判定できない場合は、失敗と断定せず判定できないことを示す。学習者は元の証明要求の全文を入力欄へ戻せる。この操作は未送信の入力を上書きせず、送信・生成・利用枠消費を行わない。再送信は学習者による通常の送信操作と利用枠の判定を必要とし、保存済みの履歴を変更しない。 |
| CORE-012 | 通常の送信は、Lean による形式検証を経た証明として回答する。学習者に Lean 検証を選ぶボタン・モード・追加の同意操作を求めない。前提確認と必要な反証判断の後、PALS は検証済み Recipe を検索する。要求と数学的内容が同一であることを独立レビューで確認できれば、保存済みの Lean source とレビュー済み回答をそのまま再利用する（CORE-002）。特殊化を含め、新しい Lean source が必要な要求は DSP で生成してコンパイルする。Draft DB の検索は DSP の Draft 段階で行う。CORE-002 を満たした証明だけを、CORE-003 の証明文とともに回答として提示する。修復の上限までに Lean が通らなかった場合は回答を提示せず、Lean で検証できなかったことを当該要求の回答言語で示し、再試行できるようにする。Lean を経ない AI だけの回答は提示しない。一般定理の具体化では、適用元・置換・前提を記録する。 |
| CORE-013 | Recipe の再利用判断と証明の採用確認は LLM と Lean が行い、学習者への同意画面を挟まない。会話から確定できず証明の意味を変える前提が不足するときだけ質問する。回答と Lean 検証の進行は同じ要求の文脈へ保存し、再読み込み後も継続できる。 |
| CORE-014 | DSP で新たに Lean 検証された証明について、学習者から追加質問がなかった場合、会話文やアカウント識別子を含めずに Draft DB への追加候補として記録する。運用者が承認したものだけを Draft DB に追加する。詳細は [draft-addition-candidates](../draft-addition-candidates/requirements.md)。 |
| CORE-015 | 各入力の回答言語は、次の順で選ぶ。(1) 利用者がその入力で行った回答言語の明示指定、(2) 学習者がアカウントで明示的に選んだ回答言語、(3) 利用者自身の依頼文の言語（明らかに別の対応言語で書かれているときだけ。この順序は[未決定事項 OQ-1](tasks.md)）、(4) アカウントの言語設定。対応言語は CORE-007 の4種とする。数式だけ、短い確認返答、判別できない入力は、直前の回答言語を引き継ぎ、直前の回答がなければチャットの初期値を用いる。PDF・画像のOCR本文、資料本文、引用、コード、選択した証明文は言語判定の対象に含めない。要求の回答言語を保存し、生成・独立レビュー・説明・失敗表示で同じ言語を用いる。追加質問も同じ順で選び、過去の回答本文と検証済み証明を変更しない。 |
| CORE-016 | アカウントを作成した直後の言語は、次の順で決める。(1) その端末で学習者が以前に選んだ画面の言語、(2) ブラウザの言語設定（`Accept-Language` または `navigator.languages`）を先頭から順に見て、最初に現れる対応言語（`en`、`ja`、`zh-Hans`、`zh-Hant`。`Hant` と `zh-TW`、`zh-HK`、`zh-MO` は `zh-Hant`、それ以外の `zh` は `zh-Hans`）、(3) 対応言語がなければ `en`。ブラウザが言語を1つも示さない場合に限り、接続元IPから得た国だけで言語を推定する（日本は `ja`、中国本土は `zh-Hans`、台湾・香港・マカオは `zh-Hant`、それ以外は `en`）。IPの国は言語を決める間だけ使い、IPアドレス、国、位置情報を学習者の記録に保存しない。ブラウザが対応外の言語だけを示す場合は、IPを使わず `en` とする。決めた言語は、画面の言語と回答の既定の言語の両方に適用する。学習者はいつでも変更できる。言語設定が未保存の既存アカウントも、次の利用時に同じ規則で決める。ゲストの画面の言語と回答言語も、同じ規則で初期化する。 |
| CORE-017 | 確認の質問（選択肢を含む）、前提や流儀の確認、失敗・待機・再試行の表示など、PALS が回答の過程で生成する学習者向けの文言は、モデルが生成するものも PALS の定型文も、当該要求の回答言語を用いる。メニュー、設定、操作ボタンなどの画面部品は、画面の言語を用いる。定型文は4言語すべてを備え、特定の言語に固定しない。 |

詳細と実装中の作業契約は [proof-request-reuse](../proof-request-reuse/requirements.md) を参照する。

## Acceptance Criteria

- 自然言語の数学問題と形式的な命題のいずれも、通常の送信だけで証明要求を開始できる。Project 配下、Project 非所属、ゲストのいずれでも、提示する回答はすべて CORE-002 を満たす Lean 検証済みの証明であり、Lean 検証の選択や同意を学習者に求めない。Lean が通らなかった要求には回答本文を表示せず、検証できなかったことと再試行を示す。
- `verified` と表示する証明の Lean source は、Lean のコードとして `sorry`、`admit`、`axiom`、`constant`、`opaque`、または `unsafe` を一切含まず、その同一 source の Lean 検証に成功している。その source 内でこの証明候補の対象として一意に識別された形式的命題と元の証明要求の対応および証明候補の論理は、生成担当とは別セッションの LLM レビューに成功している。
- 正常な回答には、元の要求・確定した前提・AI が確認した論理に基づく、当該要求で選択された回答言語の連続した数学書風の証明文を提示する。形式検証済みの履歴では、検証に用いた形式的命題と Lean source にも忠実である。本文に節見出し、箇条書き、会話調の手順分割を表示せず、`Fix`、`Let`、`Set`、`Assume`、`Therefore`（各言語の同等表現）のような直接の証明文で進める。形式検証済みの履歴では、Lean tactic の逐語訳は必須ではないが、自動化された source を含め、本文は同一の検証済み証明の数学的帰結に忠実である。形式検証済みの履歴の本文の一部への追加質問に対する回答は、当該要求の回答言語で、対象の本文および同一の検証済み証明に基づく。
- 生成、Lean 検証、または証明要求と形式的命題の対応および証明候補の論理を確認する LLM レビューが失敗したときは、対象の証明候補を未検証または失敗として当該要求の回答言語で明示し、`verified` と表示しない。説明または追加回答が失敗したときは、その出力を当該要求の回答言語で失敗として明示する。これらの出力には `verified` の状態を付与せず、CORE-002 の全条件を満たして既に `verified` と表示された証明は `verified` のままとする。
- CORE-002/004 の独立証明レビューでは、有効な応答で明示された判定だけを承認・却下の記録とする。検証サービスの通信障害や有効な判定を得られない応答は、有限回の試行後に運用上の失敗として停止し、数学的な却下の記録を生成しない。検証成功へ昇格せず、保存言語で独立検証が完了しなかったことを表示する。既存履歴を推測で訂正せず、自動で再生成・利用枠消費を行わない。
- 通常の学習画面では説明を初期表示する。Lean source は学習者が source 表示操作をしたときだけ表示し、`verified` と表示された証明では、その source は `verified` 判定に使用した source と同一である。
- 証明の回答、説明または追加回答は、学習者に提示する前に生成担当とは別セッションの LLM のレビューに成功する。レビューが失敗した場合はその出力を当該要求の回答言語で失敗として明示し、証明の `verified` 状態を変更しない。
- 言語設定は `en`、`ja`、`zh-Hans`、`zh-Hant` のいずれかとして永続化し、画面の言語と回答の既定の言語に同時に適用する。回答の言語だけを別に選んだときに限り、2つは異なる。設定画面は、回答の言語が画面の言語に従っているか、明示的に別の言語が選ばれているかを示す。
- 新規アカウントの初期の言語は、ブラウザの言語設定から決まる。`ja-JP,en;q=0.8` なら `ja`、`fr-FR,ja;q=0.8` なら `ja`、`fr-FR` だけなら `en`、`zh-TW` なら `zh-Hant`、`zh-CN` なら `zh-Hans` になる。ブラウザが言語を示さない場合に限り、IPの国から推定する。IPの国、IPアドレス、位置情報は保存しない。
- 言語設定が日本語（自動で決まったものでも、手動で選んだものでも）で、回答言語を別に選んでいないとき、日本語の入力に対して、確認の質問、選択肢、失敗・待機の表示を含む全ての学習者向けの文言が日本語になる。他の3言語でも同様である。
- 回答の言語を明示的に別の言語へ選んだ学習者には、その選択が依頼文の言語や画面の言語より優先される。明示していない学習者の回答の既定の言語は、画面の言語と常に一致する。
- 学習者は Project 配下または Project に属さない形でチャットを開始できる。`New chat` とホームの証明要求送信は Project を作らずに Project 非所属チャットへ進み、Project 作成 dialog は `Create project` または `Start a project` の明示操作時だけ表示する。新しいチャットには開始時点のアカウントの既定の回答言語を初期値として保存する。証明要求、説明、追加回答、失敗表示および状態表示には CORE-015 で選択した言語を用いる。アカウントの言語設定または回答言語を変更しても、既存チャットの初期値と生成済みの履歴は変わらない。
- Chat 導入前から存在する各 proof job は、Project に属さない専用のチャットへ移行し、そのチャットには `ja` を保存する。
- 数式記号の表示設定はアカウントごとに永続化され、同じアカウントで利用する別端末でも取得できる。設定を適用しても、Lean source の表示・コピーは検証に用いた原文と一致し、証明の検証状態は変わらない。
- 再開可否の取得は本人が所有するジョブに対する読み取りだけであり、ジョブ状態・生成権・キュー・本文を変更しない。通常の待機や経過時間だけを理由に再開不能と判断しない。保存済みチェックポイントと対象候補の整合性を確認できない場合は、再開不能や検証失敗と断定しない。
- 元の文を入力欄へ戻す操作には、省略された履歴プレビューではなく所有権を確認した証明要求全文を用いる。未送信の入力がある場合は保護し、操作のみで自動送信・外部モデル呼び出し・利用枠消費が発生しない。通常の送信操作で利用枠を消費することを示す。
