# PALS Product Requirements

## Purpose

PALS の最小体験は、数学の問いを送信し、Lean による形式検証を経た証明とその自然言語の証明文を得ることです。学習者に検証経路の選択を求めません。Lean を経ずに作られた過去の回答は、その証拠に即した状態で引き続き閲覧できます。
この文書は学習者に見える振る舞いだけを定義し、実現方法は定義しません。

## Requirements

| ID | Requirement |
|---|---|
| CORE-001 | 学習者は、自然言語の数学問題または形式的な命題を証明要求として送れる。 |
| CORE-002 | Lean による形式検証済みの証明として表示する場合に限り、PALS は証明候補を生成し、その証明の Lean source が Lean のコードとして `sorry`、`admit`、`axiom`、`constant`、`opaque`、または `unsafe` を一切含まず、その実際の Lean 検証に成功し、その source 内でこの証明候補の対象として一意に識別された形式的命題が元の証明要求に対応し、証明候補の論理が妥当であることを生成担当とは別セッションの LLM がレビューして成功した場合だけ、その証明を `verified` と扱う。Lean Recipe Catalog の登録済み Recipe を再利用する場合は、その Recipe が登録時に同一 source・同一 toolchain fingerprint で Lean 検証に成功した記録を持ち、その fingerprint が現在の検証環境と一致することを、その source の実際の Lean 検証の成功とみなす（再コンパイルしない）。命題の対応と論理のレビュー条件は同じとする。 |
| CORE-003 | 正常な回答には、元の要求・確定した前提・AI が確認した論理に基づく、当該チャットに保存された言語の数学書風の証明文を提示する。形式検証済みの履歴では、検証に用いた形式的命題と Lean source にも忠実でなければならない。証明文は節見出し、箇条書き、会話調の手順分割を用いず、`Fix`、`Let`、`Set`、`Assume`、`Therefore`（各言語の同等表現）のように直接本文を進める。形式検証済みの履歴では、Lean tactic の逐語訳は要求せず、自動化された source であっても検証済みの定理と数学的帰結に忠実でなければならない。形式検証済みの履歴では、学習者は本文の一部について追加質問でき、その証明文に基づく当該チャットの言語の回答を受け取れる。 |
| CORE-004 | 生成、Lean 検証、または証明要求と形式的命題の対応および証明候補の論理を確認する LLM レビューが失敗した場合、成功を捏造せず、対象の証明候補を未検証または失敗として当該チャットの言語で明示する。説明または追加回答が失敗した場合は、その出力を当該チャットの言語で失敗として明示する。CORE-002 の全条件を満たして既に `verified` と表示された証明は、後続する説明または追加回答が失敗しても `verified` のままとする。 |
| CORE-005 | Lean source を持つ証明では、学習者はその source を確認できる。`verified` と表示された証明では、確認する source は `verified` 判定に使用した source と同一である。通常の学習画面では説明を初期表示し、Lean source は学習者が source 表示操作をしたときだけ表示する。 |
| CORE-006 | PALS は証明の回答、説明または追加回答を学習者に提示する前に、生成担当とは別セッションの LLM によって、要求・確定した前提・論理との整合性をレビューする。形式検証済みの履歴の出力では、対象の検証済み証明（追加回答では対象の説明も）との整合性もレビューする。レビューに成功した出力だけを提示し、レビューが失敗した場合はその出力を当該チャットの言語で失敗として明示する。証明の `verified` 状態は変更しない。 |
| CORE-007 | 学習者は、英語 (`en`)、日本語 (`ja`)、簡体中文 (`zh-Hans`)、繁體中文 (`zh-Hant`) から出力言語をアカウント設定として選択できる。設定は永続化し、未設定時は英語を用いる。 |
| CORE-008 | 学習者は Project 配下または Project に属さない形でチャットを開始できる。`New chat` とホームの証明要求送信は Project を作成せず、Project に属さないチャットを開始または選択して続行する。Project 作成 dialog は `Create project` または `Start a project` の明示操作時だけ表示する。PALS はチャットの開始時に、その時点のアカウントの出力言語を当該チャットの言語として保存する。証明要求、説明、追加回答、失敗表示および状態表示は当該チャットに属し、保存した言語を用いる。アカウントの出力言語を変更しても、既存のチャットの言語は変更しない。 |
| CORE-009 | Chat 導入前から存在する各 proof job は、Project に属さない専用のチャットに移行する。PALS はそのチャットの言語を日本語 (`ja`) として保存する。 |
| CORE-010 | 学習者は、検証済み証明の説明および補足回答で使う数式記号の表示設定をアカウント設定として保存できる。保存済み設定は同じアカウントで利用する端末間に反映する。設定は数式の学習者向け表示だけを変え、証明要求、Lean source、検証に用いた形式的命題、生成済み本文、および証明の検証状態を変えない。 |
| CORE-011 | 保存情報から自動再開できないと確認された処理には、進行中の表示に代えて理由を当該チャットの言語で示す。保存情報が不整合で判定できない場合は、失敗と断定せず判定できないことを示す。学習者は元の証明要求の全文を入力欄へ戻せる。この操作は未送信の入力を上書きせず、送信・生成・利用枠消費を行わない。再送信は学習者による通常の送信操作と利用枠の判定を必要とし、保存済みの履歴を変更しない。 |

| CORE-012 | 通常の送信は、Lean による形式検証を経た証明として回答する。学習者に Lean 検証を選ぶボタン・モード・追加の同意操作を求めない。PALS はまず Draft DB で類似の証明を探す。LLM が要求と同一と判断し、その Draft に登録済みの Recipe があれば、その Lean を再利用する（CORE-002）。一般定理の特殊化であれば代入した Lean をコンパイルする。それ以外は DSP で Lean を生成してコンパイルする。CORE-002 を満たした証明だけを、CORE-003 の証明文とともに回答として提示する。修復の上限までに Lean が通らなかった場合は回答を提示せず、Lean で検証できなかったことを当該チャットの言語で示し、再試行できるようにする。Lean を経ない AI だけの回答は提示しない。一般定理の具体化では、適用元・置換・前提を記録する。 |
| CORE-013 | Draft の再利用判断と証明の採用確認は LLM と Lean が行い、学習者への同意画面を挟まない。会話から確定できず証明の意味を変える前提が不足するときだけ質問する。回答と Lean 検証の進行は同じ要求の文脈へ保存し、再読み込み後も継続できる。 |
| CORE-014 | DSP で新たに Lean 検証された証明について、学習者から追加質問がなかった場合、会話文やアカウント識別子を含めずに Draft DB への追加候補として記録する。運用者が承認したものだけを Draft DB に追加する。詳細は [draft-addition-candidates](../draft-addition-candidates/requirements.md)。 |

詳細と実装中の作業契約は [proof-request-reuse](../proof-request-reuse/requirements.md) を参照する。

チャットに入力した数式の表示と画像添付・画面改修は[chat-experience](../chat-experience/requirements.md)が定義する。証明以外への回答範囲は同仕様の未決事項であり、CORE-012を緩める決定ではない。

## Acceptance Criteria

- 自然言語の数学問題と形式的な命題のいずれも、通常の送信だけで証明要求を開始できる。Project 配下、Project 非所属、ゲストのいずれでも、提示する回答はすべて CORE-002 を満たす Lean 検証済みの証明であり、Lean 検証の選択や同意を学習者に求めない。Lean が通らなかった要求には回答本文を表示せず、検証できなかったことと再試行を示す。
- `verified` と表示する証明の Lean source は、Lean のコードとして `sorry`、`admit`、`axiom`、`constant`、`opaque`、または `unsafe` を一切含まず、その同一 source の Lean 検証に成功している。その source 内でこの証明候補の対象として一意に識別された形式的命題と元の証明要求の対応および証明候補の論理は、生成担当とは別セッションの LLM レビューに成功している。
- 正常な回答には、元の要求・確定した前提・AI が確認した論理に基づく、当該チャットに保存された言語の連続した数学書風の証明文を提示する。形式検証済みの履歴では、検証に用いた形式的命題と Lean source にも忠実である。本文に節見出し、箇条書き、会話調の手順分割を表示せず、`Fix`、`Let`、`Set`、`Assume`、`Therefore`（各言語の同等表現）のような直接の証明文で進める。形式検証済みの履歴では、Lean tactic の逐語訳は必須ではないが、自動化された source を含め、本文は同一の検証済み証明の数学的帰結に忠実である。形式検証済みの履歴の本文の一部への追加質問に対する回答は、当該チャットの言語で、対象の本文および同一の検証済み証明に基づく。
- 生成、Lean 検証、または証明要求と形式的命題の対応および証明候補の論理を確認する LLM レビューが失敗したときは、対象の証明候補を未検証または失敗として当該チャットの言語で明示し、`verified` と表示しない。説明または追加回答が失敗したときは、その出力を当該チャットの言語で失敗として明示する。これらの出力には `verified` の状態を付与せず、CORE-002 の全条件を満たして既に `verified` と表示された証明は `verified` のままとする。
- CORE-002/004 の独立証明レビューでは、有効な応答で明示された判定だけを承認・却下の記録とする。検証サービスの通信障害や有効な判定を得られない応答は、有限回の試行後に運用上の失敗として停止し、数学的な却下の記録を生成しない。検証成功へ昇格せず、保存言語で独立検証が完了しなかったことを表示する。既存履歴を推測で訂正せず、自動で再生成・利用枠消費を行わない。
- 通常の学習画面では説明を初期表示する。Lean source は学習者が source 表示操作をしたときだけ表示し、`verified` と表示された証明では、その source は `verified` 判定に使用した source と同一である。
- 証明の回答、説明または追加回答は、学習者に提示する前に生成担当とは別セッションの LLM のレビューに成功する。レビューが失敗した場合はその出力を当該チャットの言語で失敗として明示し、証明の `verified` 状態を変更しない。
- アカウントの出力言語設定は `en`、`ja`、`zh-Hans`、`zh-Hant` のいずれかとして永続化する。設定がない場合は `en` を用いる。
- 学習者は Project 配下または Project に属さない形でチャットを開始できる。`New chat` とホームの証明要求送信は Project を作らずに Project 非所属チャットへ進み、Project 作成 dialog は `Create project` または `Start a project` の明示操作時だけ表示する。新しいチャットには開始時点のアカウントの出力言語を保存し、そのチャットに属する証明要求、説明、追加回答、失敗表示および状態表示に用いる。アカウントの出力言語を変更しても、既存のチャットの言語は変わらない。
- Chat 導入前から存在する各 proof job は、Project に属さない専用のチャットへ移行し、そのチャットには `ja` を保存する。
- 数式記号の表示設定はアカウントごとに永続化され、同じアカウントで利用する別端末でも取得できる。設定を適用しても、Lean source の表示・コピーは検証に用いた原文と一致し、証明の検証状態は変わらない。
- 再開可否の取得は本人が所有するジョブに対する読み取りだけであり、ジョブ状態・生成権・キュー・本文を変更しない。通常の待機や経過時間だけを理由に再開不能と判断しない。保存済みチェックポイントと対象候補の整合性を確認できない場合は、再開不能や検証失敗と断定しない。
- 元の文を入力欄へ戻す操作には、省略された履歴プレビューではなく所有権を確認した証明要求全文を用いる。未送信の入力がある場合は保護し、操作のみで自動送信・外部モデル呼び出し・利用枠消費が発生しない。通常の送信操作で利用枠を消費することを示す。

## Working delta — 2026-10-05

ユーザーは2026-10-05に「Lean 検証はこのプロダクトの核であり絶対に残す」と明示し、通常送信を Draft 再利用 → 特殊化の代入版コンパイル → DSP 生成とコンパイル → 自然言語化の流れに戻すことを指示した。Lean が通らない場合は回答を出さない。Draft DB への追加は候補登録と運用者の承認による。ゲストも同じく Lean 必須とする。これにより、2026-09-30・10-02 の「Lean を実行しない通常回答」（`llm_assessed`）は新規の回答では使わない。保存済みの `llm_assessed` 回答はそのまま閲覧できる。

## Working delta — 2026-09-30

CORE-011 は、ユーザーが依頼した「処理中のまま止まる不具合の修正」と履歴の使いやすさ改善に対する作業中の要件である。実装・実行時検証の証拠を揃えるまで全体の完了や公開を意味しない。

CORE-002/004 のレビュー障害の区別は、独立 QA が実際に判定していない結果を却下として記録する実装不具合への作業中の修正である。元の候補・生成セッション・source の照合は維持し、新しいレビュー結果を過去の履歴へ付け替えない。
