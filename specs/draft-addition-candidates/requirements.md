# Draft addition candidates

Status: WORKING — ユーザーの2026-10-05の指示（DSP で検証された証明は、追加質問がなければ Draft DB に追加する）と、同日の決定（候補として登録し、運用者が承認してから追加する）に基づく。

## Purpose

学習者の質問から DSP で新たに Lean 検証された証明を、次の質問で再利用できるように Draft DB へ育てる。誤った・重複した Draft や学習者の会話を共有カタログに混入させない。

| ID | Requirement |
|---|---|
| DAC-001 | 証明要求に紐付く Lean ジョブが DSP（または特殊化の代入版）で `verified` となり、その説明が独立レビューに通ったとき、PALS はその証明を1件の追加候補として記録する。カタログ再利用（PFR-010）の回答は候補にしない。同じ Lean source と形式命題の候補は重複して作らない。 |
| DAC-002 | 候補には、形式命題、検証に使った Lean source とその SHA-256・toolchain fingerprint・コンパイル記録の参照、独立レビュー済みの自然言語の証明文、その証明が依拠した Draft の参照だけを保存する。学習者の質問文・会話・追加質問・アカウント識別子・Project 情報は保存しない。 |
| DAC-003 | 候補の作成から24時間以内に、その証明への追加質問が1件でもあれば候補は承認対象外とする。24時間経過して追加質問がない候補だけを承認対象として運用者に示す。 |
| DAC-004 | 候補の一覧・承認・却下は、学習者・worker・agent からは行えない運用者専用の操作とする。承認・却下は理由コード付きの不変の記録として残し、却下や承認済みの候補を再度承認・却下できない。 |
| DAC-005 | 承認された候補は、既存の Draft カタログ登録と Lean Recipe・alignment の登録手順（LRC-004/005）を通ってのみ Draft DB と Recipe Catalog に入る。本番では次の署名付き Draft カタログリリースで取り込み、ローカルでは承認コマンドから同じ登録手順を実行できる。承認だけで既存の Draft や Recipe を変更・選択可能にしない。 |
| DAC-006 | Draft DB に追加された証明は、以後の証明要求の Draft 検索の対象になる。追加済みの候補の元になった過去の回答と証拠は変更しない。 |

## Acceptance

- DSP で検証された回答1件につき候補が1件でき、会話文・アカウント識別子を含まない。カタログ再利用の回答では候補ができない。
- 24時間以内に追加質問があった候補は承認対象に出ない。
- 学習者・worker の資格情報では候補の一覧・承認ができない。
- 承認した候補が登録手順を通って Draft DB に入り、次の同一の質問がカタログ再利用（PFR-010）になる。
