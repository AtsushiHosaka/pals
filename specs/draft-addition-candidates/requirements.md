# Draft addition candidates

Status: WORKING — ユーザーの2026-10-05の指示（DSP で検証された証明は、追加質問がなければ Draft DB に追加する）と、同日の決定（候補として登録し、運用者が承認してから追加する）に基づく。

## Purpose

DSP で新たに Lean 検証された証明を、次回は Recipe から直接再利用できるように登録する。新規生成に使う証明方針も Draft DB に登録する。誤った・重複した Draft や学習者の会話を共有カタログに混入させない。

| ID | Requirement |
|---|---|
| DAC-001 | 証明要求に紐付く Lean ジョブが DSP（または特殊化の代入版）で `verified` となり、その説明が独立レビューに通ったとき、PALS はその証明を1件の追加候補として記録する。カタログ再利用（PFR-010）の回答は候補にしない。同じ Lean source・verifier image・verifier digest・出力言語・回答 SHA-256 の候補は重複して作らない。別言語や別回答は混同しない。 |
| DAC-002 | 候補には、形式命題、検証に使った Lean source とその SHA-256・toolchain fingerprint・通常の隔離 verifier の実成功を記録した不変の receipt とコンパイル記録の参照、独立レビュー済みの自然言語の証明文と出力言語、Lean source に対応する検索用の命題説明と証明方法、その証明が依拠した Draft の参照だけを保存する。検索用の説明は形式命題・検証済み source から作り、元の質問文を転載しない。学習者の質問文・会話・追加質問・アカウント識別子・Project 情報は保存しない。 |
| DAC-003 | 各元ジョブを候補に紐付けた時点から24時間以内に、その証明への追加質問が1件でもあれば候補は承認対象外とする。すべての元ジョブで24時間経過して追加質問がない候補だけを承認対象として運用者に示す。 |
| DAC-004 | 候補の一覧・承認・却下は、学習者・worker・agent からは行えない運用者専用の操作とする。承認・却下は理由コード付きの不変の記録として残し、却下や承認済みの候補を再度承認・却下できない。 |
| DAC-005 | 承認操作は、Lean Recipe と検索・回答エントリの登録手順（LRC-004/015/017）、既存の Draft カタログ登録を通ってのみ Recipe Catalog と Draft DB に入る。alignment を作る場合は LRC-005 を満たすが、次回の Recipe 検索・再利用の前提にはしない。本番では次の署名付き Draft カタログリリースで取り込み、ローカルでは承認コマンドから同じ登録手順を実行できる。Recipe、Draft、検索・回答エントリの順に実登録し、最後のエントリ公開と `approved` 記録を同じ transaction で確定する。途中失敗は段階ごとの receipt を残して再開でき、両方への追加済みとは報告しない。既存の署名付き Draft データは書き換えず、独立に登録した追加分だけを公開する。 |
| DAC-006 | Draft DB に追加された証明は、以後の DSP Draft 段階の検索対象になる。Recipe と検索・回答エントリが登録済みなら、次回の同じ数学的内容の要求は Draft DB を読まずに再利用できる。追加済みの候補の元になった過去の回答と証拠は変更しない。 |

## Acceptance

- DSP で検証された回答1件につき候補が1件でき、会話文・アカウント識別子を含まない。カタログ再利用の回答では候補ができない。
- 24時間以内に追加質問があった候補は承認対象に出ない。
- 学習者・worker の資格情報では候補の一覧・承認ができない。
- 承認した候補が登録手順を通って Draft DB に入り、次の同じ数学的内容の質問が Draft 検索なしのカタログ再利用（PFR-010）になる。

登録の一部だけが成功しても「両方に追加済み」とは記録しない。各登録先の結果と不変の参照を残し、同じ候補の再実行で重複登録しない。
