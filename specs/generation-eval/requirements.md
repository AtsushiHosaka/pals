# 生成側の評価セット: 要件

関連: 傘 Issue [#327](https://github.com/AtsushiHosaka/pals/issues/327)、Codex の説明品質評価 PR [#311](https://github.com/AtsushiHosaka/pals/pull/311)（Issue #216）。棚卸しは [inventory.md](inventory.md)、設計は [design.md](design.md)。実装は pals-agent の `pals_agent/evals/`、`scripts/eval/`、`testdata/generation-eval-v1/`。

## 目的

Draft → Sketch → Prove → Lean → 修復 の**生成側**で、変更が Lean 成功・修復回数・時間・費用を変えたかを、偶然と区別して判定できるようにする。これまでの測定は 12・24・36 枚・各1回・日ごとに別のベースで、10/12 と 11/12 を区別できなかった。

## 非目標

- 説明の品質、QA の誤拒否、公開の受入は測らない（Codex の評価が持つ）。
- 本番の応答時間は測らない（開発 Mac の秒数は相対比較にだけ使う）。
- カタログのカードは追加しない（拡張は停止中）。既存の記録の文を、問いとして使うだけ。

## 要件

| ID | 要件 | 受け入れ基準 |
|---|---|---|
| R1 | 固定の問題集合を約100題で持つ | `manifest.json` に 100 題。ID 一意、文面の SHA-256 を持つ。足りない層は埋めず不足を書く（下の表） |
| R2 | 層化する: 分野・難度・言語・既知の失敗 | 分野 ≥12、難度 easy/medium/hard 全て（easy は 30 題以下）、ja と en。修復を使い切った題と命題不一致の履歴がある題を各5題以上 |
| R3 | 調整用70・保留30に分け、保留は固定する | 分割は (salt, id, 分野, 難度) だけで決まる決定的な関数。ID・分割・文面ハッシュの SHA-256 を `SPLIT.sha256` に固定し、テストで照合 |
| R4 | 保留は最終比較でだけ開ける | `--open-held-out` を明示しない限り実行計画に出さない。開けた理由は journal に書く。開けた後の題は調整に使わない |
| R5 | `(x+y)^2` の展開を使わない | 検証テストが文面と固定 Lean 文を正規表現で検査 |
| R6 | Codex の題と ID で結合できる | 共有題 18 は `pq-<Codex の id>` と `shared.fixture_sha256` を持つ。Codex の2題（概念のみ・Lean 不要）は生成側から除く |
| R7 | 対比較: 同じ題・同じ設定・時間を交互に | 実行計画は題ごとに2腕を連続させ、腕の順を釣り合わせ、反復ごとに題を並べ替える。モデル ID・推論量・フラグを実行の記録に残す |
| R8 | 反復は2回以上。分析の単位は題 | 反復は題の中で平均し、題を単位にブートストラップする（反復を独立標本に数えない） |
| R9 | 最小検出効果（MDE）を出して過読を防ぐ | 区間が 0 をまたぐ指標は「効果は確認できない」と書く。MDE は下表を報告に添える |
| R10 | 1試行ごとの記録（段・時刻・トークン・エラーコード・失敗した Lean 本文） | 追記専用 JSONL、閉じたスキーマ。問題文・秘密・利用者内容は入れない |
| R11 | 安い層を先に使う | Tier 0 は費用0、Tier 1 は Sketch だけ。Tier 2 以上は予算の規則に従う |
| R12 | 利用者から見た成功は別指標 | Lean 成功（生成側）と、意味審査・QA を通って回答が届いた率（利用者側）を混ぜない |

## 指標の所有（Codex との分担）

| 指標 | 持ち主 | 結合の鍵 |
|---|---|---|
| 初回コンパイル、最終 Lean 成功、修復回数、モデル時間、Lean 時間、トークン、費用、失敗コード | この評価（生成側） | 題の ID（`pq-` 付きの題は `shared.prompt_quality_id`） |
| 説明の5指標（正しさ・論理・記号・明瞭・簡潔）、QA の誤拒否、回答到達率 | Codex（#311、observability） | `case_id` = SHA-256(Codex の id)、`fixture_sha256` |
| 利用者から見た成功 | 両者の結合: 生成の成功 AND 説明が届き QA を通る | 題の ID と実行 ID |

台帳は同じ `docs/quality-ledger/ledger.csv` を使い、family で区別する（生成側は `proof_generation`）。

## 現在の層別の件数（100題）

分野: calculus-analysis 31、linear-algebra 22、discrete-logic 8、algebraic-geometry 6、number-theory 6、multivariable 5、commutative-algebra 4、school-algebra 4、abstract-algebra 3、coordinate-geometry 2、exp-log 2、probability-ode 2、sequences-limits 2、trigonometry 2、topology 1。難度: easy 25、medium 50、hard 25（根拠は observed 42・assigned 39・declared 19）。言語: en 61、ja 39。分割: 調整 70、保留 30。履歴: 実測あり 42、修復を使い切った題 7、命題不一致の履歴 9。

**不足（埋めていない）:** 高校の分野（trigonometry・exp-log・sequences-limits・coordinate-geometry・probability-ode は各2題）と topology（1題）は、保留に入る題がないか1題にとどまる。理由: 高校の候補カードに Lean の証明がなく（成立するか未確認）、`(x+y)^2` 系の除外後に残りも少ない。この分野の主張には v1 を使わず、v2 で枠を広げる（決定事項 D4）。calculus と linear-algebra は過半（53%）で、全体の成功率は両分野に引っ張られる。分野別の数字を必ず併記する。

## 最小検出効果（検出力80%、両側5%）

対比較で、この差より小さい真の差は検出できない。成功率（割合の差）は、題ごとに腕の結果が食い違う割合 π に依存する。時間は、題ごとの差の標準偏差 75 秒を仮定する（2026-11-09 の保留24枚の秒数差の区間 [−79.3, −20.1] から逆算した値で、別の題集合では変わる）。

| n（題） | 成功率の差 π=0.1 | π=0.2 | π=0.3 | 平均秒数の差 |
|---:|---:|---:|---:|---:|
| 24（過去の測定） | 18.1 点 | 25.6 点 | 31.3 点 | 42.9 秒 |
| 30（保留） | 16.2 点 | 22.9 点 | 28.0 点 | 38.4 秒 |
| 70（調整） | 10.6 点 | 15.0 点 | 18.3 点 | 25.1 秒 |
| 100（全体） | 8.9 点 | 12.5 点 | 15.3 点 | 21.0 秒 |

読み方: 70 題でも、成功率の 5 点の改善は検出できない（π=0.2 で 15 点が下限）。成功率の小さな差は、このセットでも判定できない。時間と修復回数は連続値なので、成功率より小さな差を見分けられる。判定できない差は、判定できないと書く。

## 費用の層（モデルを呼ぶ層ほど少数で）

| 層 | 内容 | 費用の目安 | 承認 |
|---|---|---|---|
| Tier 0 | 保存した Lean 出力を実 Lean で再検査（検証器・決定的処理の変更） | 0 | 不要 |
| Tier 1 | Draft を固定し Sketch だけ再生成して `sorry` 許容でコンパイル | 約 US$0.02/題（Draft+Sketch の実測 0.019 が上限） | 1 回の比較が US$1 以内なら不要 |
| Tier 2 | 全工程の煙テスト 12 題 | 1腕1反復で約 US$0.84（12 × 0.070）。2腕では約 US$1.7 で上限を超える | 1ドル以内に収める（片腕、または6題×2腕） |
| Tier 3 | 全工程、調整70×2反復×2腕 | 約 US$19.6（0.070/題の場合）。100題は約 US$28、保留30だけは約 US$8.4 | **要承認**（見積もりを添える） |

## 決定事項（オーナー）

- D1 Tier 3 の予算（上の見積もりのどれを承認するか）と、実行場所（開発 Mac は負荷が高い。AWS の dev か、本番停止中の時間帯）。
- D2 保留30題の扱い: 開ける回数の上限と、Codex の `prospective_holdout`（開封済みで以後は回帰用）との整合。
- D3 難度の根拠: observed 42 以外は、題の構造からの手動割り当て（assigned 39）か記載の難度（declared 19）。割り当てを見直すか。
- D4 高校の分野の拡張（カタログ追加は停止中なので、問いとしてだけ使う候補を増やすか）。
